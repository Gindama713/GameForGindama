# 睡眠过渡（入睡 / 醒来）实现方案

> ## ✅ 已于 2026-09-22 实现完毕 —— 落地记录见 `事实文档.md` §5.6g
>
> **本文保留为设计初衷与推演过程的记录**，实现时有三处被实测修正：
> 1. **缓动曲线**：`smoothstep` → `u^1.5`（smoothstep 的反函数是三次方程，而"过渡中途改方向"必须要反函数 —— 见坑 44）。
> 2. **§7.1 待拍板项**：**保留**了"按一下 R 叫醒自己"（它是唯一的中断退路），走渐进醒来。
> 3. **验证方法**：§6.2 的"像素比对"**不足** —— 本地图 98% 是黑土，拿暗色压黑土反而变亮，量到的全是内容差。
>    正确做法是**固定 zoom + 垫纯白底反解 alpha**（见坑 48）。§6.1 的时序探针则完全有效，且**抓到了一个真 bug**。
>
> **实测结果**：时序探针 **8/8** · 像素探针 **6/6**。

> 目标：**入睡与醒来要有"生理感"，而不是一次瞬移。**
> 用户原话：`睡觉的时候能长按R 然后画面逐渐微微放大 画面微微变暗大概5-6秒` ·
> `醒来同理 缓缓回归正常视野 画面变成正常亮度（若不是自然醒而是惊醒则直接醒来）` ·
> `此是为了实现真实的入睡醒来体验`

## 一、别的游戏怎么呈现"睡觉"（凭了解，非查证）

### 三种范式

| 范式 | 做法 | 代表 | 代价 |
|---|---|---|---|
| **A. 跳过式（黑屏）** | 淡出到全黑 → 直接到第二天早上，黑屏当"结算画面" | Stardew Valley · Valheim · Skyrim | 便宜，但**把夜里发生的一切都抹掉了** |
| **B. 半暗 + 时间流逝（保留可见）** | 只压暗，不遮死；时间快进，玩家还能看见世界在动 | Red Dead Redemption 2 · The Long Dark · Project Zomboid | 需要处理"暗到什么程度还看得清" |
| **C. 相机运动 + 延时摄影** | 镜头推近/拉远，或用天空快速流动表达时间流逝 | RDR2（缓缓推近到角色）· BotW/TotK（篝火睡觉时天空在跑）· Minecraft（相机升到床上方俯视） | 需要额外美术/表现 |

**我们已经否掉了 A**（用户 2026-09-21 拍板走"把夜晚当后台"：**加速而不是跳过**，
理由是"跳过 = 夜里没危险了，睡觉变成无风险的免费回血"）。
所以本方案是 **B 为主 + C 的一半（推近）** —— 正好就是用户描述的那个组合。

### 从这些游戏里能提炼出的四条"真实感"规律

1. **不对称**：**入睡慢、醒来快。**
   真实的入睡是几分钟的渐进过程；醒来是突发的（睁眼那一下就已经清醒七八成）。
   所以过渡时长**不应该对称** —— 这是"真"与"假"最明显的分界线。

2. **非线性**：**没有一款游戏用线性插值做这个。**
   线性过渡一眼就假。入睡要"先几乎没变化、然后越来越沉"；醒来要"一睁眼就回来大半、剩下慢慢收尾"。

3. **形状是"眼皮"不是"暗角"**：
   真实的闭眼是**上下眼皮合拢**（水平方向收窄），不是从四角收拢的圆形暗角。
   所以暗角应该是**竖向压扁的椭圆** —— 上下先暗，左右后暗。

4. **醒来那一下要"有对比"**：
   惊醒之所以是"惊"，恰恰因为它**没有过渡** —— 从最暗到全亮是一帧完成的。
   这个"跳"本身就是效果，不需要额外加闪白。

## 二、★ 最关键的技术发现：过渡**不能**跑在加速态里

这一条如果不想清楚，整个功能是错的。

`SleepDirector` 现在的逻辑是：**只要主角在睡，`TimeSystem.speed` 就是 30。**
而"入睡过渡 5.5 秒"是**真实秒**。两者相乘：

```
5.5 真实秒 × 30 倍 = 165 游戏分 = 2.75 个游戏小时
```

**一夜（20:00→06:00）只有 600 游戏分。** 也就是说：**光是那 5.5 秒的过渡，就会吃掉整个夜晚的 27%。**
玩家按一下 R，什么都没看清，天就亮了。

⇒ **过渡期间必须 `speed = 1`；只有过渡跑完（t 到 1）才允许加速。**

这一条同时决定了架构：**"过渡进度"和"时间倍率"必须是同一个节点持有的两个状态**，
因为它们之间有因果依赖。不能一个放 UI、一个放 world。

## 三、设计

### 3.1 参数（全是占位，跑出来再调）

| 常量 | 值 | 说明 |
|---|---|---|
| `FALL_SECONDS` | `5.5` | 入睡过渡时长（**真实秒**，用户要 5-6 秒）|
| `WAKE_SECONDS` | `4.0` | 自然醒过渡时长。**故意比入睡短** —— 见 §1 规律 1 |
| `ZOOM_IN` | `1.14` | 入睡时的**额外**放大倍率（**乘在玩家当前 zoom 上**，不是覆盖）|
| `DARKEN_CENTER` | `0.10` | 画面中心额外压暗（"微微变暗"）|
| `DARKEN_EDGE` | `0.34` | 画面边缘额外压暗（暗角），叠在中心之上 |
| `TINT` | `Color(0.03, 0.02, 0.06)` | 偏冷蓝紫，**不是纯黑** —— 夜里已经有一层黑，再叠纯黑会糊成一团 |
| `BREATHE_AMP` | `0.015` | 熟睡时暗角的**极缓呼吸波动**（可选打磨项）|

### 3.2 曲线（非线性，这是"真"的关键）

设 `u ∈ [0,1]` 是过渡的时间进度，`t ∈ [0,1]` 是视觉强度。

```
入睡：t = u² · (3 − 2u)          # smoothstep：起步轻 → 中段快 → 末段轻轻沉下去
醒来：t = (1 − u)²               # 先快后慢：一睁眼就回来大半，剩下是"缓过来"
惊醒：t = 0（一帧）              # 没有过渡就是效果本身
```

- 入睡在 `u=0.5`（2.75 秒）时 `t=0.5`，全程可感知，不会让玩家以为"按了没反应"。
- 醒来在 `u=0.2`（0.8 秒）时 `t=0.64` —— **已经回来 36%**，这就是"睁眼"的手感。

### 3.3 视觉由两件事构成

| 组成 | 谁来做 | 怎么改 |
|---|---|---|
| **微微放大** | `world/camera_rig.gd` | `zoom = base_zoom × lerp(1.0, ZOOM_IN, t)` —— **相乘**，保留玩家手动缩放的意图 |
| **微微变暗** | 新建 `ui/sleep_fade.gd` + `.gdshader` | 全屏 `ColorRect` + 暗角 shader，`t` 作为 uniform |

**为什么暗角用竖向压扁的椭圆**：见 §1 规律 3。`vec2(1.0, 1.35)` 把 y 拉长 ⇒ 上下先到阈值 ⇒ 像眼皮合拢。

### 3.4 三种醒来，各走各的

| 醒来方式 | `Sleep.wake_reason()` | 过渡 |
|---|---|---|
| **自然醒** | `睡够了` / `睡太久了` | 渐进 `WAKE_SECONDS` |
| **惊醒** | `附近有动静` | **一帧归零** |
| 主动唤醒 | `自己按醒了` | 渐进（若保留该功能，见 §七）|

**为什么拆成"一个导演 + 两个哑消费者"**：符合项目 §6.5 解耦纪律 ——
`camera_rig` 与 `sleep_fade` **都不认识 `Sleep` 组件、也不认识时间倍率**，
它们只认识一个 `float t`。将来要加第三个消费者（音频、手柄震动）不用动前面任何一处。

### 4.2 `Sleep` 加类型化的唤醒原因（顺手修掉一处字符串耦合）

现在 `SleepDirector` 要判断"是不是惊醒"，只能比字符串 `"附近有动静"` —— 典型的同值复制，
改一个字就静默失效。⇒ 让 `Sleep` 暴露类型：

```gdscript
## 唤醒原因（类型化）。**别再让外部比字符串** —— 那是同值复制，改一个字就静默失效。
enum Wake { NONE, RESTED, TOO_LONG, DISTURBED, MANUAL }

func wake_kind() -> Wake: ...
```

`SleepDirector` 只判 `_sleep.wake_kind() == Sleep.Wake.DISTURBED`。

### 4.3 `SleepDirector` 的视野状态机

```
        ┌──────────────────────────────────────────────────────┐
        │                                                      │
   AWAKE ──is_sleeping()──> FALLING ──u到1──> ASLEEP ──!is_sleeping()──> RISING ──u到1──> AWAKE
   t=0  speed=1             t:0→1     speed=30  t=1  speed=30          t:1→0  speed=1
                            speed=1                                        ↑
                            │                                              │
                            └──────!is_sleeping()──────────────────────────┘
                                   （被打断：惊醒 → 直接 t=0 回 AWAKE）
```

```gdscript
enum View { AWAKE, FALLING, ASLEEP, RISING }
var _view := View.AWAKE
var _u := 0.0            # 过渡的时间进度 0..1
var _t := 0.0            # 视觉强度 0..1（由 _u 经曲线算出）
var _emitted := -1.0

func _process(dt: float) -> void:
    _step_view(dt)
    _apply_speed()
    _emit_view()

func _desired_speed() -> float:
    # ★ 关键改动：从前是 `is_sleeping()`，现在是 `_view == View.ASLEEP`
    #   否则过渡那 5.5 秒会以 30 倍速跑掉 165 游戏分（见方案 §二）
    return SLEEP_SPEED if _view == View.ASLEEP else NORMAL_SPEED
```

⚠ **必须有的超时兜底**：如果 `_view` 因为任何原因卡在 `FALLING`，
时间就**永远不加速**（睡眠功能静默失效）。所以 `FALLING` 要有硬上限
（如 `2 × FALL_SECONDS`），超了强制进 `ASLEEP`。这是"状态机不能有死路"的纪律。

⚠ **主角死亡要回 AWAKE**：`SleepDirector` 已有"判主角有效性"（防世界永远 30 倍速）。
视野状态机要跟着一起回 —— 否则**主角死后画面会永远暗着**。

### 4.4 暗角 shader（草案）

```glsl
shader_type canvas_item;

uniform float t : hint_range(0.0, 1.0) = 0.0;
uniform float darken_center : hint_range(0.0, 1.0) = 0.10;
uniform float darken_edge   : hint_range(0.0, 1.0) = 0.34;
uniform vec4  tint : source_color = vec4(0.03, 0.02, 0.06, 1.0);

void fragment() {
    // 竖向压扁的椭圆：y 乘 1.35 ⇒ 上下先到阈值 ⇒ 像眼皮合拢（不是正圆暗角）
    vec2 p = (UV - vec2(0.5)) * vec2(1.0, 1.35);
    float d = length(p);
    float edge = smoothstep(0.26, 0.62, d);
    float a = t * (darken_center + edge * darken_edge);
    COLOR = vec4(tint.rgb, clamp(a, 0.0, 0.92));
}
```

用 `UV` 而不是 `SCREEN_UV`：`ColorRect` 铺满整屏，`UV` 就是屏幕坐标，
且**不需要 `BackBufferCopy`**（少一层开销，也不用管渲染顺序）。

### 4.5 相机：zoom 改为"基准 × 睡眠因子"

```gdscript
var _base_zoom := 1.0        # 玩家自己选的缩放（滚轮改它）
var _sleep_t := 0.0          # 由 EventBus.sleep_view_changed 喂

func _apply_zoom() -> void:
    var z := _base_zoom * lerpf(1.0, ZOOM_IN, _sleep_t)
    zoom = Vector2(z, z)
```

⚠ **必须相乘，不能覆盖**：`_zoom_at_mouse()` 现在直接写 `zoom`。
如果睡眠过渡直接写 `zoom = ZOOM_IN`，玩家手动放大到 2.0 之后一睡觉就被拉回 1.14 ——
"我明明放大了，睡一觉给我缩回去了"。相乘则 2.0 → 2.28，语义正确。
`_zoom_at_mouse()` 里"保持鼠标下的世界点不动"那段要用 `_base_zoom` 重算，别用 `zoom`。

### 4.6 `main.tscn` 节点位置

```
UI (CanvasLayer)
├─ NightOverlay      ← 夜色（现有）
├─ SleepFade         ← 新增，排在这里：盖住世界，但**不压暗 HUD**
├─ CreatureInspector
├─ Minimap
├─ TimeDisplay
├─ PlayerHud         ← 保持明亮可读（睡眠期间玩家还要看状态）
└─ PlayerPanel
```

**为什么排在 `NightOverlay` 之后**：沿用现有约定（`NightOverlay` 是"盖住生物、不压暗其它 UI"的第一子节点）。
HUD 在睡眠期间必须可读 —— 那是玩家唯一能确认"我在睡、时间 ×30"的地方。

⚠ **白天/夜里要各截一张图确认可读性**：夜里 `NightOverlay` 已经是 0.55，
再叠睡眠暗角，**四角会到 0.55+0.10+0.34 ≈ 0.78**。中心 0.55+0.10 = 0.65。
这个数在白天没问题，夜里可能偏暗 —— **必须实截确认，不能凭算**。

### 4.7 时序上的一处小不协调（已知，接受）

`Sleep.ONSET_MIN = 2.0` 游戏分。过渡期间 `speed=1`，所以 ONSET 只持续 **2 真实秒**，
而视觉过渡要 5.5 秒 —— 也就是**机制上已经"睡着了"（感知 ×0.35）时，画面才走到 36%**。

- 为什么接受：视觉是**表现层**，它滞后于逻辑是正常的（就像动画有过渡帧而状态已经切了）。
- 如果一定要对齐，唯一干净的做法是**把视觉时长也交给 `Sleep`** —— 但那等于把表现塞进逻辑组件，
  违反 §6.8「表现与逻辑分离」。**不建议。**
- 实际影响：过渡期间如果被吵醒，画面会立刻弹回 —— 语义正确（"刚迷糊一下就被吵醒了"）。

## 六、验证方案

### 6.1 探针（时序，最重要）

按 `godot-headless-probe` 那套：独立探针场景把 `main.tscn` 当子节点装进来。
⚠ **这次不能用 `TimeSystem.speed = 60` 加速** —— 我们要测的正是真实秒。用真实时间跑 ~20 秒。

断言：

| # | 断言 | 判据 |
|---|---|---|
| ① | 入睡过渡时长 | `t` 从 0 到 1 耗时 ≈ `FALL_SECONDS`（±0.3 秒）|
| ② | **过渡期间不加速** | `t < 1` 期间 `TimeSystem.speed == 1` **每一帧**成立 |
| ③ | 过渡完成后才加速 | `t` 首次到 1 之后 `speed` 才变 30 |
| ④ | **惊醒瞬时** | 强制 `wake_up("附近有动静")` → 下一帧 `t == 0` 且 `speed == 1` |
| ⑤ | 自然醒渐进 | 强制自然醒 → `t` 从 1 到 0 耗时 ≈ `WAKE_SECONDS` |
| ⑥ | 入睡期间被打断 | `t` 到 0.5 时惊醒 → 立刻回 0，不卡在 0.5 |
| ⑦ | 主角死亡 | 杀掉主角 → `t` 回 0、`speed` 回 1 |
| ⑧ | 超时兜底 | 人为把 `_view` 卡在 `FALLING` → 超时后仍能进 `ASLEEP` |

### 6.2 像素验证（视觉）

项目有先例（渲染层拆分做过 **983,040 像素 / 0 差异** 的比对）。这里反过来用：

- 在 `t=0` 与 `t=1` 各截一张（**截前先 `cam.position = player.position`**，
  否则相机的指数平滑相位不同，比对会被污染 —— 这个坑踩过）。
- 断言：`t=1` 的**四角**像素明显变暗、**中心**轻微变暗、**可见世界范围缩小**（zoom 生效）。
- 再做一张**夜间**的（`TimeSystem.elapsed` 设到 22:00），确认可读性 —— 这是 §4.6 那个 ⚠ 的落点。

### 7.1 睡着时还能不能主动醒来？

你说的是 `算了自然醒渐进就好了 不需要按r`。现在代码里**已经有一处**主动唤醒：
`PlayerBrain` 里"按一下 R 叫醒自己"（`sl.wake_up("自己按醒了")`）。

| 选项 | 后果 |
|---|---|
| **A. 删掉**（照你说的） | 最干净。但**一旦睡着就没有退路** —— 想半夜起来做点什么、或者按错了想取消，都做不到 |
| **B. 保留**（我倾向） | 多一个逃生阀。误触风险其实不大（疲劳 ≥95% 时 `start()` 本来就拒绝），但"想提前醒"是真需求 |

**删掉只是一个 `else` 分支**，随时可以改。你定。

### 7.2 醒来时长要不要和入睡一样？

你说"醒来同理"，我建议**故意短一点**（入睡 5.5 / 醒来 4.0），理由见 §1 规律 1（真实里醒来比入睡快）。
要完全对称就把 `WAKE_SECONDS` 改成 5.5 —— 一个常量的事。

### 7.3 变暗的程度

"微微变暗"我按 **中心 +10% / 四角 +34%** 设计。夜里叠上夜色可能偏暗（见 §4.6 ⚠）。
**建议先按这个值做出来，截图看了再调** —— 这类"多少算微微"必须用眼睛定，算不出来。

## 八、不做的（明确排除，免得被当成漏做）

| 项 | 为什么不 |
|---|---|
| **模糊 / 景深** | 2D 像素风上做模糊基本只会变糊，不是"失焦感"。收益低、开销真。 |
| **音频（环境音渐弱、心跳）** | **项目现在完全没有音频系统**（`project.godot` 里没有 `AudioServer` 总线、没有任何 `AudioStreamPlayer`）。要做得先建音频层，那是独立的一件事。 |
| **全黑（眼皮完全合拢）** | 与"把夜晚当后台"冲突 —— 全黑就看不见世界了，等于变相"跳过"。 |
| **睡姿贴图 / 角色躺下** | 属睡眠阶段 3~4 的表现项（见事实文档 §8.1），与本次过渡是两件事。 |
| **猪的睡眠过渡** | 猪没有相机、没有全屏 UI。过渡是**主角专属**的表现，和体力圈（`SprintArc` 从 `pig.tscn` 移除）同一个道理。 |
