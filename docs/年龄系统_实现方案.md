# 年龄系统 · 设计与实现规划（Aging / Life Stages）

> 状态：**规划草案（未实现）**，供评审后再动手。作者：QoderWork · 2026-09-19
> 唯一事实基准仍是 `事实文档.md`；本文件描述「打算怎么做」，落地后回写进事实文档。
> 设计准绳取自 godot 技能 + 本项目纪律：数据驱动 Resource、组件协议解耦、`TimeSystem` 固定 tick、可复现 RNG、`die()` 唯一执行、基类不认识具体组件、只新增少改动、不提前抽象。

---

## 0. 一句话与核心判断

给每只生物加**年龄**：随游戏时间增长 → 经历**生命阶段（幼崽 / 成年 / 老年）** → 到**寿命上限老死**。

关键判断：**"老死"正是本项目预留的标准扩展点**——事实文档 §5.3/§6.6 写明「加一种死法 = 加一个组件重写 `is_lethal()` + `lethal_reason()`，`die()` 与 tick 循环一行都不动」。所以年龄系统**不碰生死内核**，只新增一个 `Aging` 组件报告"寿终"。体型/速度等阶段效果也走既有协议（外观聚合、Brain 读组件），不改基类。

## 1. 实体定义

### 1.1 `LifeDef`（Resource，物种级「一生怎么过」）—— `creature/life_def.gd`
仿 `NeedDef`/`PersonalityDef`：只放数值，加物种改 .tres。

```gdscript
class_name LifeDef
extends Resource
@export var lifespan_min: float = 8640.0   # 自然寿命（游戏分）。到点老死。[占位]=6游戏日
@export var juvenile_ratio: float = 0.20   # 年龄 < 寿命×此比 = 幼崽
@export var elder_ratio: float = 0.75      # 年龄 ≥ 寿命×此比 = 老年（其后到寿终）
@export var variance: float = 0.15         # 个体寿命 ±15%（由 creature.rng 派生，可复现）
# —— 阶段效果（MVP 只做体型/速度；HP/代谢留后）——
@export var size_juvenile: float = 0.5     # 幼崽精灵缩放（相对成年 1.0）
@export var size_elder: float = 0.9        # 老年略萎缩
@export var speed_juvenile: float = 1.6    # 幼崽决策间隔倍率（>1=更慢/更笨拙）
@export var speed_elder: float = 1.3       # 老年更慢
@export var fertile_min_ratio: float = 0.20 # 成年可繁殖下限（为将来繁殖系统预留，MVP 不接）
@export var fertile_max_ratio: float = 0.75 # 老年不育上限
func validate() -> Array[String]: ...  # lifespan>0；0<juvenile<elder<1；倍率>0；比例区间合法
```
`creature/pig/pig_life.tres` = 猪的一份。

### 1.2 `Aging`（组件）—— `creature/components/aging.gd`
```gdscript
class_name Aging
extends CreatureComponent
enum Stage { JUVENILE, ADULT, ELDER }
var age_min: float = 0.0
var lifespan_min: float = 0.0     # setup 时 = def.life.lifespan_min × rng(1±variance)
func requires() -> Array: return []        # 自足，只读 def.life
func setup(host): super.setup(host); lifespan_min = _roll_lifespan(); age_min = _spawn_age()
func tick(dt): age_min += dt; _maybe_announce_stage()   # 跨阶段时通知宿主刷新外观
func stage() -> Stage: ...
func is_lethal() -> bool: return age_min >= lifespan_min            # ← 老死，走既有协议
func lethal_reason() -> String: return "老死（活了 %.1f 天）" % (age_min/1440.0)
func speed_factor() -> float: ...          # 幼/老 >1，成年 1.0（Brain 读它调决策间隔）
func visual_scale() -> float: ...          # 幼 0.5→成年 1.0 线性长个，老年微缩（协议聚合，见 §2）
func debug_state() -> String: return "年龄%.1f天/%.0f天 %s" % [...]  # 自动进调试合成属性
```

### 1.3 `CreatureDef` 加一个字段
`@export var life: LifeDef`（可空 = 该物种**不挂年龄**，行为完全不变，向后兼容）。`Aging` 从 `creature.def.life` 读参数。`validate()` 增 life 校验；`DefValidator` 已扫 `res://creature`，pig_life.tres 自动被校验。

## 2. 与现有系统的接线（全部走既有扩展点，不改内核）

| 效果 | 接法 | 是否碰基类/内核 |
|---|---|---|
| **老死** | `Aging.is_lethal()/lethal_reason()` → 基类 `check_dead_state()` 统一接线 | 否（§5.3 扩展点）|
| **体型随年龄** | 给 `CreatureComponent` 加协议 `visual_scale() -> float`（默认 1.0），`Aging` 覆写；`Creature._render/_apply_appearance` 聚合各组件 `visual_scale()` 乘到精灵 scale（仿 `is_concealed()` 聚合） | 基类只加一个通用协议遍历，不认识 Aging |
| **速度随年龄** | `Brain._reset_timer()` 里 `base = move_interval × (Aging.speed_factor() if 有)` —— Brain 本就直接读 Personality/Perception，读 Aging 一致 | 否 |
| **阶段切换刷新外观** | `Aging` 跨阶段时调宿主 `creature.refresh_appearance()`（基类一个通用小方法，内部重跑 _render/聚合），或发 `EventBus` 信号 | 基类加一个不针对组件的通用刷新入口 |
| **调试可见** | `Aging.debug_state()` 自动进 `Creature._get_property_list()` 的 `debug/components/aging` 行 | 否（现成机制）|
| **检视面板** | 可选加一行"年龄/阶段"；不加也已能在调试器看到 | 否 |
| **启动校验** | `LifeDef.validate()` + `DefValidator` 扫到 | 否 |
| **可复现** | 寿命个体差异用 `creature.rng`（世界种子派生）→ 同种子同猪同寿命 | 否 |

**新信号（可选）**：`EventBus.creature_grew(creature, new_stage)`，供将来（体型动画、繁殖触发、日志）监听。MVP 可只发日志。

## 3. 时间尺度与"一生多长"

- 1 游戏日 = 1440 游戏分 = 24 真实分钟。
- 猪 `lifespan_min` 占位 **8640 = 6 游戏日 ≈ 2.4 真实小时**：够你看着一代生老病死，又不至于几分钟就死完。真实猪 6~10 年——本系统按"玩法可观察"压缩，不追真实（数值全 `[占位]`，跑起来再调）。
- 阶段切分（默认 6 日寿命）：幼崽 0~1.2 日、成年 1.2~4.5 日、老年 4.5~6 日、6 日老死。

## 5. 分期里程碑（每期 headless 可验，探针用完即删、断言式输出）
- **A1 年龄内核 + 老死**：`LifeDef`+`Aging`+`CreatureDef.life`+校验；pig 挂上。探针：spawn 一只，快进 `age`，断言到 `lifespan` 时 `is_dead_state()` 真、`die()` 走通、死因含"老死"、同种子寿命一致、`--quit-after` 无报错。**这一步就能"会老死"了。**
- **A2 阶段 → 体型 + 速度**：加 `visual_scale()` 协议 + Brain 读 `speed_factor()`。探针：幼崽 scale<1、老年速度倍率>1、成年=1；跨阶段刷新外观。
- **A3 出生年龄策略**：决定刷猪是"幼崽/随机年龄/成年"（见 §6 Q4），实现之。
- **A4（决策后）繁殖**：若要做种群延续，加"成年+附近有异性→生幼崽（继承性格/寿命 rng）"——这是**下一套系统**，年龄是它的前置。MVP 可不做，先用 debug 刷补充。
- **A5 平衡**：寿命 vs 代谢/繁殖/草场承载力，让种群能自我维持或按设计衰减。

## 6. 需要你拍板（先问不擅自假设）
- **Q1 范围**：MVP 做到哪层？(a) 只「涨岁数 + 老死」；(b) +「幼/成/老三阶段 → 体型/速度」；(c) 再 +「HP/代谢随年龄、老年体弱易死」。我建议 **b**（c 的 HP/代谢改动会牵动 Body/Needs，宜单独一期）。
- **Q2 繁殖**：现在就接"成年能生"让种群延续，还是先只做老死（种群只减、靠 debug 刷补充）？我建议**先只做老死**，繁殖留 A4 单开一期。
- **Q3 寿命尺度**：6 游戏日（≈2.4 真实小时）合适吗？还是想更快（1~2 日看一代）或更慢更"真实"？
- **Q4 刷猪默认年龄**：现在"刷猪"出的是成年猪。有了年龄系统后默认应：(a) 幼崽(age0，看它长大)；(b) **随机年龄**(开局就有老有小，最好看，我推荐)；(c) 保持成年。
- **Q5 老死强度**：纯固定寿命 vs ±15% 个体差异（我推荐后者，rng 派生、可复现）。

## 7. 风险
- **只老死不新生 → 种群归零**：若 Q2 选暂不繁殖，刷进去的猪会陆续老死、世界变空。属预期（可再刷）；要"活的世界"必须补 A4 繁殖。
- **体型改精灵 scale 与"逐格铺"渲染**：生物精灵缩放已按 CELL_SIZE/纹理宽算，再乘 visual_scale 要确保幼崽不溢出格、点击选仍按格坐标（不受 scale 影响，选点是反算格子）。
- **协议膨胀**：`visual_scale()` 是给基类加的第 5 个组件协议——要确认真的通用（只有年龄用），否则宁可让表现层自己 `get_component(Aging)`（像 Inspector 读 Body/Needs 那样），别硬塞基类。这点我倾向：**先让 `Creature._render` 直接 `get_component(Aging)` 读 scale**（表现层认识组件是允许的，UI 就这么干），比给基类加协议更轻。评审时定。
