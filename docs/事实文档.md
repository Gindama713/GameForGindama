## 一、项目目标与范围

### 1.1 一句话

一个 **2D 网格荒岛求生模拟游戏**：玩家落魄荒岛，靠采集 / 制作 / 建造 / 应对动植物活下来。
系统深度优先于画面表现——目标是「每个动作都有后果、世界会自己运转、故事由系统叠加涌现」，而不是剧本。

> 说明：以上为项目**长期目标**。就当前代码而言，**玩家与荒岛都还不存在**（见 §1.3）。

### 1.2 设计支柱（决定一切取舍的根）

| 支柱 | 含义 | 对架构的强制要求 |
|---|---|---|
| 模拟深度优先 | 不追求画面，追求因果链完整 | 逻辑层与表现层可分离；表现删掉不影响模拟 |
| 涌现式叙事 | 不写剧本，靠系统叠加出故事 | 系统之间不写死交互，靠状态组合 |
| 数据驱动内容 | 物品/配方/生物/地块用数据定义 | 加内容不改代码 |
| 后果与永久死亡 | 错误有代价，死亡有终结 | 生死必须是单一事实来源，不可歧义 |
| 可读性 | 图标 + 文字 + 事件日志 | 世界状态要能被「读懂」，不靠美术暗示 |

### 1.3 范围

**在范围内（最终要做）**：时间与昼夜、岛屿地形、玩家属性与代谢、分部位伤害与伤病、背包（重量+体积）、制作与技能、天气与温度、火、动植物生态、庇护所建造、水源与净化、食物保存、探索与地图记忆、存档。

**当前代码实际拥有的**（截至本文档日期）：
- 一个逻辑网格（**130×130** = 16900 格）+ **DF 式贴图地图渲染**（每格铺 `grass.png` / `high-grass.png` 贴图、无图才用 `Terrain` 注册表的 color 兜底、NEAREST 像素）+ **右上角小地图**（**只显示当前视野**那一片，随相机移动，自适应 ≤150px，地形底图 + 生物色块）
- **一套世界地貌与生成**（2026-09-19）：`unknown`（世界底·占位）+ `grass` / `tall_grass` 三地形 + **一块椭圆草原**·噪声边界生成器（`GrasslandGenerator`：草原**中心落在离地图正中半径 50 的圆周上随机取点**、大小/胖瘦/朝向随种子变、整片恒落在 130×130 图内、封顶 ~11 格）
- **一台可平移 / 放大相机**（`CameraRig`：默认 `zoom=1.0`=原一屏 40×24、`MIN_ZOOM=1.0` 不许缩小、中键拖动 / WASD 平移、滚轮放大到 4.0；开局**不**自适应全图）
- 一套窗口自适应（画面随窗口等比放大）
- 一个全局时钟（可暂停/倍速的接口，但无控制界面）
- 一群会自己随机走动的**猪**（唯一存在的生物，主画面是 `creature/pig/art/pig.png` 剪影；小地图上是 `def.map_color` 白点）
- 它的身体部位 / 需求 / 出血 / 死亡（要害失能、饥渴冻致死两条死法）+ **高草隐蔽** + **吃草**（猪现为 **8 个组件**，新增 `Grazing`）
- **一套草场系统**（2026-09-19）：`GrassField` Autoload 持有活草 → 耐久（吃秃）/ 再生（不吃回春）/ 扩散（成熟格向 3×3 邻域定殖）；`GrassDef`(Resource)+`GrassTile`(RefCounted)+`grazing.gd` 组件 + `Brain` 觅食驱动（详见 §5.1e）
- 一个调试工具栏 + 一个生物检视面板（含活体/尸体两种视图）
- 一套 EventBus 信号与日志出口
- **一套启动期定义校验**（配数据错了会当场报错，而不是运行期静默出事）

**明确还没做**（不许当已有）：
- **玩家角色**（没有 avatar，没有输入控制）。相机已在，但**没有"跟随目标"**，靠手动拖。
- **TileMap 节点**（地形贴图已接：用 `draw_texture_rect` 逐格铺 `world/art/grass.png` / `high-grass.png`，**没用** Godot 的 TileMap 节点；自动拼接 / 多图层将来再考虑）
- 物品、背包、制作、技能、战斗、驯化
- 天气、温度场、水源、火
- 存档 / 读档
- 除猪以外的任何生物

> 记忆点：**现在的项目是一个「生物模拟内核 + 调试壳」，不是一款能玩的游戏。**

**窗口自适应（2026-09-18 实测，非推测）**

判定方法：冻结时钟 + 打开检视面板 + 截图，扫非黑像素包围盒（内容边界），换窗口尺寸比对。

| 窗口 | 渲染区域 | 内容包围盒 | 结论 |
|---|---|---|---|
| 1280×768 | 1280×768 | (8,8)-(668,408) | 基准 1x |
| 1920×1152 | 1920×1152 | (12,12)-(1004,612) | **×1.5 等比放大**（三个坐标都精确 ×1.5） |
| 1600×900（16:9，比例不同） | 1500×900 | (12,12)-(784,476) | 取 `min(1.25, 1.172)=1.172` 等比缩放，左右各 50px 黑边，**不变形** |

- 改前是 `aspect="expand"`：窗口变大只会**多露出空白**，画面不放大 —— 与"随窗口放大"的诉求相反。
- `scale_mode="integer"` 实测：1920×1152 下渲染区域仍是 **1280×768（1x，不放大）**，因为装不下 2x（2560×1536）。所以整数倍模式虽然像素最锐利，但**拉大窗口没反应**；要"随窗口放大"必须用 `fractional`（代价：非整数倍时像素略有不匀）。

**两条规律**（加东西时照这个想）：

1. **顶层按领域分**：`common/`（基础设施）、`creature/`（生物）、`world/`（世界表现）、`ui/`（界面）、`assets/`（共享资源）、`docs/`（文档）。
2. **框架与具体实例分离**：`creature/` 放基类与组件，`creature/pig/` 放猪的一切。
   → 加一只狼 = 新建 `creature/wolf/`（场景 + def + art + data），**不动框架**；删掉一个物种 = 删一个文件夹。

**注意事项**：

- 目录名统一 **snake_case**（官方规范：Windows/macOS 文件系统不区分大小写、Linux 区分，而导出的 PCK 虚拟文件系统**区分**；`Sand Crab` 这种带空格/大写的写法不要学）。
- `pig/data/` 里的部位与需求 .tres 目前是**猪私有的**（"头 40 血"是猪的数值，不是通用模板）。
  等第二种生物出现、发现数值真重复时，再把通用部分上提到 `creature/defs/`（即 §8.3 的 `BodyPlanDef`）。**现在不提前抽象。**
- 暂不建 `stages/` `localization/` `config/`：现在没有对应需求（多关卡、文本翻译、独立配置文件），建了就是空壳。
- 早期《荒岛求生开发计划.md》画的 `data/ core/ world/ entities/ tools/` 目录树**没有采用**；以本节为准。

### 2.4 已实测的 Godot 4.7 本地坑

| # | 坑 | 现象 | 绕法 |
|---|---|---|---|
| 1 | `.tres` 里用内联子资源 `type="ClassName"`（ClassName 是 GDScript 全局类） | `Cannot get class 'X'` / `Can't create sub resource of type 'X'`，类已注册进缓存也照样失败 | 改**独立 `.tres` 文件**（顶层 `script_class="X"`），引用处用 `ExtResource` 按路径引用 |
| 2 | 在主场景里 `instance = ExtResource(...)` 实例化「根脚本在 `_ready` 里 `add_child` 子节点」的 UI 场景 | 被 Godot 实例系统整段丢弃（`WARNING: modified from inside an instance, but it has vanished`），节点变 null | 不要实例外部 UI 场景；把 UI 作为**主场景的直接节点**（parent 写好）挂脚本 |
| 3 | 给 `Sprite2D` 赋 `input_pickable` | 在本 4.7 构建下赋值报错 | 不走 picking，用坐标查格反算做点击选取（见 §5.8） |
| 4 | 引擎重写 `project.godot` | 用户写的 `;` 注释被删；**等于引擎默认值的键被移除**（`window/stretch/aspect="keep"`、`scale_mode="fractional"`）；section 重排（`[autoload]` 挪到前面） | 实测是**一次性迁移**：把键写回后再 `--import` 不会再吞（已验证）。被删 ≠ 行为变了 —— `ProjectSettings.get_setting()` 实测仍是 `keep` / `fractional`（它们本就是 4.7 默认值）。**解释性注释同时写进本文档**，别只留在 `project.godot` 里 |
| 5 | **搬动/重命名脚本后不重新导入就跑** | 满屏 `Parse Error: Cannot infer the type of "x" variable because the value doesn't have a set type` + `ERROR: Failed to load script "res://..." with error "Parse error"` —— 因为 `.godot/global_script_class_cache.cfg`（全局 `class_name` 注册表）还指向旧路径，`Grid` / `CreatureDef` 等类型解析不出来，**看起来像代码坏了，其实只是缓存过期** | 搬完**先 `--headless --import`** 再实跑（顺带还会重建 `.godot` 里的映射）。本项目 2026-09-19 目录重构时实测踩到过 |
| 6 | **`Control.set_anchors_preset(PRESET_TOP_WIDE)` 想让控件通栏** | anchors 确实变成 `(0,0,1,0)`，但**控件尺寸仍保持原最小尺寸**（Label 只有文本宽 ~163px、贴左边），于是 `horizontal_alignment=CENTER` 只在这窄盒子里居中 → 文字跑到**左上角**（以为「没居中」） | **显式写 anchors 与 offsets**（`anchor_left=0; anchor_right=1; offset_left=0; offset_right=0`），或用 `set_anchors_and_offsets_preset()`。2026-09-19 顶部时钟实测踩到 |
| 7 | **`:=` 遇 `creature.rng.*`（Variant）** | `Parse Error: Cannot infer the type of "r" variable`（`var r := creature.rng.randf() * total`）—— `creature.rng` 是 Variant，链式调用推不出类型 | 显式标类型：`var r: float = ...`。同日 Brain v2 写轮盘时踩到 |
| 8 | **删探针脚本后 `.uid` 残留** | Godot 给每个 `.gd` 生成同名 `.uid`；`rm 探针.gd` 后 `.uid` 还在，`git add -A` 会把它提交进去（本次 `_probe_night.gd.uid` 中招） | 删探针要 **`.gd` + `.uid`（+ `.tscn`）一起删**；提交前用 `git ls-files \| grep -i probe` 自查 |

## 三、运行时骨架

### 3.1 Autoload（8 个，声明顺序即初始化顺序）

| 名称 | 脚本 | 职责 | 依赖 |

### 3.2 场景树

```
Main (Node2D, res://main.gd)                        ← run/main_scene
├─ MapRenderer (Node2D, res://world/map_renderer.gd)   ← 把网格画成贴图地图（grass/high-grass 逐格铺）
├─ Creatures (Node2D)                                   ← 场上所有生物都挂这里（见下方「为什么要容器」）
├─ Camera2D (Camera2D, res://world/camera_rig.gd)        ← 可平移/放大相机（默认 zoom=1.0 不缩小，2026-09-19）；UI 在 CanvasLayer 里，不受它影响
├─ UI (CanvasLayer)
│  ├─ NightOverlay (ColorRect, res://ui/night_overlay.gd) ← 夜晚压暗全屏（UI 第一个子节点：盖住生物、不压暗其它 UI）
│  ├─ CreatureInspector (PanelContainer, res://ui/creature_inspector.gd)
│  ├─ Minimap (Control, res://ui/minimap.gd)             ← 右上角小地图（锚点 TOP_RIGHT，margin 8）
│  └─ TimeDisplay (Label, res://ui/time_display.gd)      ← 顶部中央时钟「第 N 天 HH:MM」（TOP_WIDE 居中、不吃鼠标，2026-09-19）

运行时动态生成（挂在 Creatures 下）：
Pig (Node2D, res://creature/creature.gd)
└─ Sprite2D                       ← 有 texture 的物种走图片；无 texture 的物种走 _draw 色块兜底
```

> **为什么要给生物一个容器**（2026-09-19，用户提出「善用节点、便于调试」后落地）：
> 生物原先直接挂 Main，与渲染器 / UI 平级混在一起 —— 场景树里看不出「场上有什么」；
> 清屏也只能靠 `is Creature` 类型过滤去 Main 的子节点里翻，将来 Main 下多挂一个节点就有误伤风险。
> 现在生成与清空只经 `Creatures` 一个口：`Main._spawn_pig()` 写入、`Main.clear_creatures()` 清空。
>
> **绘制顺序是硬约束**：兄弟节点按树序绘制，后画的在上层。所以 `Creatures` 必须排在 `MapRenderer`
> **之后**，否则地表色块会盖住生物。当前排列已实测确认：窗口模式截图里猪在 (656,400) 正常可见。

### 3.3 时间与节拍

- 时钟源：`TimeSystem._physics_process(delta)`（物理帧，固定步长 → 确定性）。
- 物理 tick 频率**未配置**，用引擎默认。
- 推进公式：`d = delta * speed`；`elapsed += d`；`tick.emit(d)`。
- `paused == true` 时**直接 return，不发 tick** → 所有订阅者自然停止。
- **所有生物都订阅 `TimeSystem.tick`，没有生物自己读 `_process`。** 暂停/倍速因此是免费的。
- `TimeSystem.paused` / `speed` 目前 `[休眠]`：字段存在、逻辑读它，但**没有任何代码或 UI 去设置它**（没有暂停键、没有倍速键）。

### 4.2 定义层（Resource，全局共享的「是什么」）

**`CreatureDef`**（`creature_def.gd`）— 物种数据

| 字段 | 类型 | 说明 |
|---|---|---|
| `display_name` | `String = "生物"` | 显示名 |
| `texture` | `Texture2D` | 主画面图标（猪 = `creature/pig/art/pig.png`）；**可为 null** → 主画面用 `map_color` 色块兜底 |
| `map_color` | `Color = 白` | **小地图**上的色点颜色；也是无图物种在主画面的兜底色 |
| `component_scripts` | `Array[Script]` | **声明式组合**：这个物种挂哪些组件 |
| `body_parts` | `Array[BodyPartDef]` | 部位清单；空数组 = 没有身体系统 |
| `active_needs` | `Array[NeedDef]` | 激活的需求；空数组 = 没有需求系统 |
| `personality` | `PersonalityDef` | 物种脾气分布；**可为 null** → 性格全取中性 0.5 |
| `move_interval` | `float = 1.0` | 大脑决策间隔基数（秒），物种级 `[占位]` |

**`CreatureDef.validate() -> Array[String]`**（定义校验）`[已实现]`
返回问题清单，空数组 = 通过。检查项：`display_name` 非空；部位 id 非空/不重复/`max_hp > 0`；**至少一个 `is_vital` 部位**（否则该物种天生不死）；需求 id 非空/不重复/`max_value > 0`/`drain_rate >= 0`；`move_interval > 0`；组件脚本有资源路径/不重复挂载/实例化成功/`requires()` 依赖齐全。
两处调用：**启动期**由 `DefValidator` 扫全部定义；**生成期**由 `Creature._ready()`，不通过就拒绝生成。
> 内部拆成 `_validate_parts` / `_validate_needs` / `_validate_components`。组件依赖校验**分两遍**（先收齐路径再查依赖），这样「依赖方写在被依赖方前面」不会误报。
> **不检查**「有没有 stance 肢体」—— 鱼/蛇本来就没有腿，无 stance 是合法配置。

**`BodyPartDef`**（`body_part_def.gd`）— 部位定义

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 唯一标识，如 `"head"` |
| `label` | `String = "部位"` | 中文显示名 |
| `max_hp` | `float = 100.0` | 部位血量上限 |
| `is_vital` | `bool = false` | **要害**：归零即判宿主死亡 |
| `limb_types` | `Array[String]` | 该部位承担的肢体职能集合。`"stance"`=支撑/行走，`"grasp"`=抓握。**空 = 不是肢体** |
| `category` | `String = "other"` | **仅显示/分组用，不参与任何规则判定** |

方法：`is_limb()`（`limb_types` 非空即真）、`has_limb_type(t)`。

> 设计要点（依据 CDDA `body_part_type`）：`is_vital` / `limb_types` 是**数据字段**，不是代码里 `category == "head"` 这种字符串比较。加一个要害部位、加一条腿，都只是配数据。

**`NeedDef`**（`need_def.gd`）— 需求定义

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 如 `"food"` |
| `label` | `String = "需求"` | 中文显示名 |
| `max_value` | `float = 100.0` | 上限（同时也是初始值） |
| `drain_rate` | `float = 1.0` | **每秒衰减量** `[占位]` |
| `depleted_is_lethal` | `bool = false` | **见底即死境**。由 `Needs.is_lethal()` 上报、`Creature` 统一执行。饥饿/口渴/保暖/憋气 = true；疲劳 = false |

### 4.3 运行时状态层（RefCounted，个体的「现在是多少」）

**`Creature`（生物基类）** — `class_name Creature extends Node2D`，`creature/creature.gd`

| 成员 | 类型 | 说明 |
|---|---|---|
| `def` | `CreatureDef`（`@export`） | 我是谁 |
| `coord` | `Vector2i = Vector2i.ZERO` | 我在哪一格（**逻辑位置**） |
| `_alive` | `bool = true`（**私有**） | 生死唯一事实来源。外部**只读** `is_alive()`，**只有 `die()` 能改它** |
| `id` | `int` | 全局自增编号，日志用 |
| `rng` | `RandomNumberGenerator` | **个体随机源**。按 `世界种子 + 递增序号` 派生，替代全局 `randf/randi` → 存档/回放可复现 |
| `_components` | `Dictionary` | key = 组件脚本的 `resource_path`（String） → value = 组件实例 |
| `BODY_SIZE` | `const 20.0` | 自绘色块边长（格子 32px，留边显"棋子"感） |
| `DEAD_COLOR` | `const Color(0.32,0.32,0.32)` | 死亡后的色块颜色 |

方法清单：
`tag()` / `_log_spawn()` / `_unhandled_input()` / `get_component(script)` / `has_component(script)` / `get_components()` /
`is_alive()` / `is_dead_state()` / `lethal_reason_text()` / `check_dead_state()` / `die()` /
`_on_tick(dt)` / `_build_components()` / `_fail_init(reason)` /
`can_place_at(c)` / `_place_at(c)` / `_release_cell()` / `move_to(target)` / `_draw()`

> **表现**：**有图用图**（猪 = `pig.tscn` 的 `Sprite2D` + `def.texture`）；没配 `texture` 的物种才由 `_draw()` 在格子中央画 `def.map_color` 色块兜底。死亡时：有图 → `_sprite.modulate = DEAD_COLOR`；无图 → `queue_redraw()` 后由 `_draw()` 读 `_alive` 变暗。

> **基类不认识任何具体组件。** 它没有 `get_body()` / `get_needs()` 这类便利方法 —— UI 自己知道要显示 `Body`/`Needs`，用 `get_component(Body)` 取；生成日志靠各组件提供 `debug_state()` 拼接。**加一个新组件不必回来改基类。**
> `move_to()` / `_place_at()` 返回 `bool`：越界或被占时**报错并拒绝**，不会留下 `coord` 与占格不一致的状态。

**基类只放这些东西**，因为它们对 100% 的生物都成立：我是谁、我在哪、我还活着吗、我挂了哪些组件、我占哪一格、我每帧怎么推进。

|---|---|---|
| `def` | `BodyPartDef` | 指向定义 |
| `hp` | `float` | 初始化为 `def.max_hp` |
| `bleeding` | `float = 0.0` | **每秒掉血量**。部位归零时由 `Body` 主动清零（出血结束） |
| `_half_logged` / `_down_logged` | `bool` | 日志去重标记 |

方法：`ratio()`（**带除零保护**：`max_hp <= 0` 返回 0 而非 NaN）/ `function_ok()` / `apply_damage(amount)` / `add_bleeding(amount)` / `status_text()`（失能 / 出血 / 正常）

> `infection` 字段**已删除**。它以前没有任何代码写入，导致 `status_text()` 的「感染」是个永远不出现的死分支 —— 留着比删掉更容易骗人。感染将由计划中的**状态效果系统**（CDDA 二维键，效果 × 部位）统一实现。

### 4.4 组件协议

**`CreatureComponent`**（`class_name CreatureComponent extends RefCounted`，`components/creature_component.gd`）

| 成员 | 签名 | 默认 | 说明 |
|---|---|---|---|
| `creature` | `Node` | `null` | 宿主，由 `Creature` 装配时注入 |
| `setup(host)` | `void` | 记录宿主 | 覆写时必须 `super.setup(host)` |
| `requires()` | `Array` | `[]` | 声明依赖的其他组件（**返回脚本数组**，如 `[GridMover]`） |
| `is_lethal()` | `bool` | `false` | **协议 1**：报告「宿主是否已到死境」 |
| `lethal_reason()` | `String` | `""` | **协议 1**：死因说明，写进死亡日志（基类取第一个非空项） |
| `allows_movement()` | `bool` | `true` | **协议 2**：本组件是否允许宿主移动。断腿/被捆/眩晕都重写它 |
| `debug_state()` | `String` | `""` | **协议 3**：生成日志里的一段自述。空串 = 没什么可报 |
| `is_concealed()` | `bool` | `false` | **协议 4**（2026-09-19）：本组件是否把宿主藏起来（高草）。基类聚合成 `Creature.is_concealed()`，供表现层与 `Perception` 消费 |
| `tick(dt)` | `void` | `pass` | 每帧推进，`dt` 来自 TimeSystem |

> 四个协议合起来解决同一类问题：**基类不该认识任何具体组件**。
> 少一个，就会冒出「基类里写 `get_component(Body)`」这种回头债。

**装配机制**（`Creature._build_components()`）：
`def.component_scripts` 里是 `Script` 对象 → 逐个 `.new()` → `setup(self)` → **以 `s.resource_path` 为键**存进 `_components`。
`get_component(Body)` / `has_component(Body)` 都走 `script.resource_path` 查询。

> `[已知问题]` 用**脚本资源路径**当键，意味着 `component_scripts` 里必须填 GDScript 资源本体（编辑器里拖 `.gd` 文件），不能填别的东西。`CreatureDef.validate()` 会检查这一点。

**依赖校验**：已从「只 `push_warning`」升级为 `CreatureDef.validate()` 的一部分 —— `requires()` 声明的是**硬依赖**，缺了就是配置错误，会在**启动期报错**，并在生成期**拒绝生成**该生物。

**`GridMover`**
- `DIRS`（const）：上下左右四向，不再每次调用新建数组
- `is_cell_free(c) -> bool`：在界内 且（格上无 content 或 content 是自己）
- `free_directions() -> Array[Vector2i]`：四向中可走的方向。**不能移动时返回空数组**（与 `try_step()` 保持一致，免得大脑白挑一次再被拒）
- `try_step(offset) -> bool`：先 `can_move()`，再交给 `creature.move_to()`（由后者做边界/占位校验并返回结果）
- `can_move() -> bool`：**遍历所有组件问 `allows_movement()`，全票通过才放行**

> 职责边界：**GridMover 只管「能不能移」，不管「往哪移」**。决策归大脑组件。
> 更关键：`can_move()` **不再 `get_component(Body)`**。断腿的否决来自 `Body.allows_movement()`，所以将来加「被绳索捆住 / 眩晕 / 负重超限」都不必回来改这个文件。

**`Brain`**（2026-09-19 取代 `wander_brain.gd`；同日 **v2 改为加权随机**）
- v1 = 「比大小取最大」→ **确定性**：高活力猪永远游荡（像发疯）、低活力猪夜里永远静止（像死掉）。
  v2 = **加权随机（轮盘）**：**性格只调「概率」，具体选谁随机** → 同一只猪也走走停停、时群时独。
- 5 个**驱动**，各一个权重；轮盘按权重随机挑 **1** 个执行：
  - `Wander` 游荡：随机方向走一格；权重 `0.35 + 活力×0.5`
  - `Social` 合群：有同类时权重 = 合群度，朝邻居重心走（凝聚）
  - `Separate` 独处：有同类时权重 = 1−合群度，背离最近邻居（分离）
  - `Rest` 休息：权重 = (1−活力)×**0.5** + (1−疲劳)×0.8 + **夜晚 3.0**；选中 → 原地休息（白天短歇 / 夜里长睡，回疲劳）
  - `Idle` 发呆：权重 = 0.35 + (1−活力)×0.6；选中 → 原地**短歇**（让「走」不连续）
- 权重全是 `[占位]`，跑出来再调。
- 间隔不固定：移动 = `move_interval ×(1.6−活力) ×randf(0.65,1.35)` 再乘疲劳减速；发呆 = `×randf(0.4,3.0)`；**休息 = 白天 `randf(1.5,5)` 分（短歇）/ 夜里 `randf(60,150)` 分（长睡）**，再 `×(1+(1−疲劳)×0.5)`。
- `last_drive`：上一次选中什么（`wander`/`social`/`separate`/`rest`/`idle`/`blocked`），供检视面板与调试。
- **昼夜反差**（用户 2026-09-19 拍板）：夜里 Rest +3.0 **且休息时长拉到 60~150 分** → **基本整夜在睡**；白天用短歇（1.5~5 分）→ 保持活跃。
- **睡觉回疲劳**：处于 `rest` 时按 `SLEEP_RECOVER_RATE`(0.2/游戏分钟) 调 `Needs.restore("fatigue", …)`；一夜(10 h)≈从 0 回满。
- 缺 `Personality`/`Perception` 也能跑（退化为中性游荡），不静默崩；随机数走**宿主的 `creature.rng`**（可复现）。
- 实测（探针，2026-09-19 v3）：**夜(22–04) rest 时间占比 0.99、每只只挪 ~2 次**（基本整夜在睡）；**昼(12–18) rest 0.35、每只挪 ~123 次**（活跃）—— 昼夜反差明显。轮盘分布（600 次决策）：高活力最大份额仅 .36、五种驱动全出现；低活力「歇+发呆」.61 vs 高活力 .23。
- `[已知问题]` 仍**不记上一次的方向**，所以没有惯性/对齐（鱼群对齐要用 `last_dir`，见 §8）。

**`Personality`**（性格，2026-09-19 新增）
- 6 维（各 0..1）：`aggression / bravery / dominance / energy / nervous / sympathy`（攻/勇/强/活/焦/同）。id 恒在 `IDS` 常量里。
- 出生时由 `creature.rng` 按 `CreatureDef.personality`（`PersonalityDef`）生成 → **同种子可复现**。
- 生成模式：`CORRELATED`（默认：`bravery/energy/sympathy` 独立随机，其余三维按**占位**关联公式以 `(x−0.5)` 偏移量推导）或 `PURE_RANDOM`。
- **所有维度的期望值都是 0.5**（用户 2026-09-19 拍板）：独立维 = `randfn(0.5, spread)`；派生维 = `0.5 + Σ系数×(源维−0.5)`。即「平均个体六维都落在 0.5，个体差异是对 0.5 的上下浮动」。
- `push_from_half`（默认 **0**）可把值推离 0.5（越大越极端）；为 0 时值聚在 0.5 附近。
- `get_trait(id) -> float`；`sociability() -> float` = 同情 + 焦虑 + (1−攻击) − 强势（占位权重，clamp 0..1）。
- 未配 `personality` 时全取中性 0.5 并 `push_warning`。

**`Perception`**（感知，2026-09-19 新增）
- `radius: int = 6` `[占位]`。扫 `(2R+1)²` 方块，逐格读 `GridManager.cell_at` 的 `content`。
- `neighbors() -> Array`：半径内**活着、且未隐蔽**的同类（`def` 相同），不含自己；`count()`。
- **跳过隐蔽中的生物**（2026-09-19）：藏进高草的同类看不见 → 不算邻居。
- 只读，不改任何状态。

**`Concealment`**（隐蔽，2026-09-19 新增）
- `is_concealed() -> bool`：宿主**当前格地形**是否藏匿 —— 走 `Terrain.conceals(cell.terrain)`。
- **无状态**：不存字段、不需要 `tick`。地形只在移动时变，故由 `Creature` 在 `move_to()` 成功后重新评估（见 §5.6）。
- 消费方：① 表现层「**完全看不见**」（隐藏 `Sprite2D`；无图物种由 `_draw()` 提前 return）；② `Perception` 跳过隐蔽中的生物。
- 猪已挂（`pig_def.tres` 第 7 个组件）；其它物种要不要「会藏」由数据决定。

**`PersonalityDef`**（`creature/personality_def.gd`，Resource）
- 物种级「脾气分布」：`generation_mode` / `spread`(0.18) / `push_from_half`(0.6)，均 `[占位]`。
- 6 个维度的 **id 与关联公式是框架固定的**（写在 `personality.gd`），故**没**按原方案拆 6 个 `trait_*.tres`——那只是提前抽象，等真要「按维度配分布」再拆。
- 猪用 `creature/pig/pig_temperament.tres`。

**`Body`**
- `parts: Array[BodyPart]`，`setup` 时从 `def.body_parts` 实例化
- `tick(dt)`：**事件驱动** —— 只处理 `bleeding > 0 且 hp > 0` 的部位（`hp -= bleeding * dt`，下限 0）；部位归零时**主动把 `bleeding` 清零**（出血结束）。没有出血时一个部位都不碰
- `hurt(part, damage, bleed) -> void`：**唯一的受伤入口**。调试/将来的战斗/坠落都走它，保证「扣血 → 状态变化 → 日志」只有一套逻辑
- `_note(part)`：部位跨阈值时打日志（去重，不刷屏）
- `is_lethal() -> bool` → `is_vital_down()`：**只要有 `def.is_vital` 为真且已失能的部位，就报告死境**
- `lethal_reason() -> String`：如「头 要害失能」
- `allows_movement() -> bool` → `can_locomote()`
- `debug_state() -> String`：`血=380/380 部位{…}`
- `can_locomote() -> bool`：若部位里存在 `stance` 类肢体，则要求**至少一条还活着**；若**没有任何** `stance` 肢体（鱼/蛇），返回 true（不受限）
- `total_hp()` / `total_max()`：各部位求和
- `part_by_id(id)`、`random_wound()`（调试按钮用，走 `hurt()` 入口）

> **`Body` 绝不调用 `creature.die()`。** 它只通过 `is_lethal()` 报告事实。执行由 `Creature.check_dead_state()` 统一接线。

**`Needs`**
- `needs: Array[Need]`，`setup` 时从 `def.active_needs` 实例化
- `tick(dt)`：每个需求 `value -= drain_rate * dt`（下限 0），见底时打一次日志（致命需求会标注「（致命）」）
- `is_lethal() -> bool`：**标了 `depleted_is_lethal` 的需求见底 = 死境**
- `lethal_reason() -> String`：如「口渴 耗尽」
- `restore(id, amount) -> bool`：恢复某项需求（将来的吃/喝/取暖/睡觉都调它）；返回 false = 该需求没激活
- `need_by_id(id)` / `debug_state()`：`需求{…}`
- **见底有后果了**：饥/渴/保暖耗尽会致死，堵上了「饿不死也渴不死」的洞。
  疲劳**不致死**（正确 —— 它应带来减速/强制休息）：现已接入 `Brain` —— 疲劳越低，休息权重越高、决策间隔越长，猪会**更想歇、在网格上动得更慢**。`Needs.restore("fatigue", …)` 已备好，将来「睡觉恢复疲劳」只需让 rest 状态回调它。

### 5.1b 地形与草原生成 `[已实现]`（2026-09-19）

**`Terrain`**（`world/terrain.gd`，`class_name Terrain extends RefCounted`）—— 地形的**唯一事实来源**：`id -> {label, texture, color, walkable, conceals}`。
- 常量 `UNKNOWN` / `GRASS` / `TALL_GRASS`；静态查询 `Terrain.texture_of / color_of / walkable / conceals / label_of`。
- **加一种地形 = 往 `DEFS` 加一行**，逻辑代码一行不改。
- 查不到的 id（含初始 `&"unknown"`）一律按 `UNKNOWN`：黑、**可踩**、不藏匿、无贴图。
- 表现规则与生物一致：**有贴图用贴图**（`grass` / `tall_grass` = `world/art/*.png`），无图才用 `color` 兜底。
- `[纪律]` 草原是绿的，与「纯黑白 UI 主题」互不冲突；`color` 仍用于**小地图烘底图**（1px/格）与无图兜底。
- 为什么不拆 `.tres`：现在只有两种地形、属性是「结构性」的（能否踩 / 是否藏人 / 贴哪张图），不是「每个地形一堆可调数值」；等真出现草/沙/石/水各带一堆数值时再拆 Resource（**不提前抽象**）。

| id | 显示名 | 贴图 | 颜色 (r,g,b) | walkable | conceals |
|---|---|---|---|---|---|
| `unknown` | 未知 | —（无图，画黑） | (0.00, 0.00, 0.00) 黑 | 是 | 否 |
| `grass` | 草原 | `world/art/grass.png` | (0.26, 0.45, 0.20) 绿 | 是 | 否 |
| `tall_grass` | 高草 | `world/art/high-grass.png` | (0.13, 0.27, 0.11) 深绿 | 是 | **是** |

**`GrasslandGenerator`**（`world/grassland_generator.gd`）—— 世界地貌生成器（当前只有"未知底 + 一块草原"）。
- `generate(grid, seed) -> Dictionary`：**世界默认铺 `unknown`（黑·占位）**；**一块椭圆 `grass`**，草原中心再套一小块 `tall_grass`；两层边界都由噪声扰动成不规则形状。**草原不再钉死正中**（2026-09-19 方案 B）：其**中心落在「以地图正中为圆心、半径 `RING_RADIUS(=50)` 的圆周」上随机取一点**（`ring_angle = rng.randf(0,TAU)`；`草心 = 正中 + 50·(cos,sin)`）。返回除统计外**新增 `center`(草心格坐标)/`major`(长半轴)/`ring_angle`**，供 `main` 在"草周围"放猪。
- 【大小/胖瘦/朝向仍随种子变】`major = max_major × randf(0.55,1.0)`、`ratio = randf(0.5,1.0)`（1=正圆，越小越扁）、`minor = major×ratio`、`angle = randf(0,TAU)`（椭圆自身朝向，与草心方位独立）。
- 【封顶在"整片仍在图内"·取代旧"装进40×24视野"约束】地图已扩到 **130×130**（中心到边 = 65）。草心在离正中 50 的环上，故长半轴上限按几何算死：`max_major = (半图65 − 环50)/NOISE_SLACK(1.3) ≈ 11.5` → 保证 `环50 + 草块11.5×1.3 ≤ 65`，整片恒落在图内。**代价**：环半径越大、可用草块越小——50 环上注定是 ≤11.5 的小椭圆（尺寸在上限内仍随机）。⚠ **相机不跟随**（用户定）→ 开局正中那一屏（40×24）看不到草原，须平移相机去找。
- 判定（**先绕草心转 -angle 进椭圆自身坐标系，再套归一化椭圆**）：`ex = dx·cos+dy·sin`、`ey = -dx·sin+dy·cos`（`dx=x-草心x, dy=y-草心y`）；`e_out = √((ex/major)²+(ey/minor)²)`，`e_out <= 1 + noise(x,y)*NOISE_AMP` → 属于草原（再判内层 `e_in = √((ex/tx)²+(ey/ty)²) <= 1 + noise(x+off,y+off)*NOISE_AMP` → `tall_grass`，否则 `grass`）；否则 `unknown`。
  内层半轴 = 外层 × `TALL_INNER_RATIO(0.45)`、随外层同一朝向；`NOISE_AMP = 0.30`、`FastNoiseLite`（SIMPLEX，frequency 0.125）、内层噪声采样点平移 `INNER_OFFSET` 去相关。
- **可复现**：形状 RNG、环方位 RNG 与噪声**同源于世界种子** → 同种子 = 同一张图（草心/形状/朝向/毛刺全一致；探针实测 7 颗种子：草心离中心恒 49.7~50.4、散布圆周各处、全部 `落在图内=是`、同种子两次逐字节一致）。
- **只写 `Cell.terrain`**，不碰 `content` / `corpse`。
- 实测（默认种子 20260918，130×130）：**环角 287° / 草心 (80,17) / 长 6.9 / 短 4.1 / 形向 112° / 落在图内=是**，**未知 16807 / 草原 73 / 高草 20**（130²=16900 全核；草原在 50 环上因封顶而偏小，各种子 ≈70~260 格不等）。`generate()` 打印一行 `[草原生成] …` 自检。
- 调用点：`Main._ready()` 生成 → `EventBus.terrain_changed.emit()` → `MapRenderer` / `Minimap` 重画。
- `[已实现]` 世界种子已**收敛为单一来源**：新建 Autoload `WorldSeed`（`value=20260918`），`Main`（generate）、`GrassField`（扩散 rng）、`Creature`（个体 rng）都读 `WorldSeed.value`，消掉了此前 `Main.WORLD_SEED` 与 `Creature._world_seed` 两处各写一份的债。

**可踩性**：`GridMover.is_cell_free()` 除边界/占格外，还问 `Terrain.walkable(cell.terrain)`。当前草/高草都可踩 → 行为不变；将来水面/岩壁才会真正拦人。

### 5.3 生死系统 `[已实现]` ★核心架构

**三段分离，照搬 CDDA `creature.h`：**

| 阶段 | 函数 | 归属 | 职责 |
|---|---|---|---|
| 判定 | `is_dead_state()` | `Creature` | 遍历所有组件问 `is_lethal()`，**任一为真即真** |
| 接线 | `check_dead_state()` | `Creature` | `if is_dead_state(): die()`。**每帧 tick 末尾只调这一次** |
| 执行 | `die()` | `Creature` | **全项目唯一把 `alive` 改成 false 的地方** |

`die()` 做的事，按顺序：
1. `if not _alive: return`（**幂等**：多个要害同时归零也只死一次）
2. 取死因 `lethal_reason_text()`
3. `_alive = false`
4. `TimeSystem.tick.disconnect(_on_tick)`（停机）
5. `_release_cell()`（交还占格）+ `GridManager.place_corpse(coord, self)`（**尸体永久留在格上** —— 交还 content 让活体能从这格过，但 corpse 留着，移动"万不得已"才踩；用户拍板 2026-09-19）
6. 表现变暗：有图 → `if _sprite != null and def != null and def.texture != null: _sprite.modulate = DEAD_COLOR`；随后无条件 `queue_redraw()`（无图物种靠 `_draw()` 读 `_alive` 变暗）
7. `Log.ev("死亡", "…（死因）…")`
8. `EventBus.creature_died.emit(self)`

> 死因来自组件的 `lethal_reason()`，所以日志能说清是「头 要害失能」还是「口渴 耗尽」，不再一律写成「要害失能」。

`_on_tick(dt)` 的全部内容：
```gdscript
for comp in _components.values():
    comp.tick(dt)
check_dead_state()
```
**循环里没有任何 `alive` 判断。** 判定与接线都在基类，组件不必记得自己查。

**当前存在的死法有两种**：
1. `Body` 报告「要害部位（头 或 躯干）被打到 0」。
2. `Needs` 报告「标了 `depleted_is_lethal` 的需求耗尽」（饥饿 / 口渴 / 保暖）。

> 扩展方式：**加一种死法 = 加一个组件并重写 `is_lethal()` + `lethal_reason()`**。`die()` 与 tick 循环一行都不用动。

### 5.4 身体与伤害系统 `[已实现]`

- 部位清单来自数据（猪有 6 个：头 / 躯干 / 前左腿 / 前右腿 / 后左腿 / 后右腿）。
- **总血 = 各部位 hp 之和**（不是独立血条）。所以「总血」是派生量，不是存储量。
- 伤害走**唯一入口** `Body.hurt(part, damage, bleed)`；调试、将来的战斗/坠落都调它。
- 出血：`BodyPart.bleeding`（每秒）在 tick 里扣该部位 hp。**部位归零时出血自动清零**（出血结束）。`[未决]` 还没有主动止血/包扎。
- `[未决]` 感染 —— `infection` 字段已删除，将由状态效果系统实现（见 §8.3）。
- `[未决]` 部位连接关系（父/对侧/子部位）、加权肢体类型 —— 见 §8.3。

**部位状态 → 能力的映射（涌现式，不查表）**：

| 部位状态 | 后果 | 实现处 |
|---|---|---|
| `is_vital` 部位失能 | 宿主死亡 | `Body.is_lethal()` |
| 所有 `stance` 肢体失能 | 不能移动 | `Body.allows_movement()` → `GridMover.can_move()` |
| `grasp` 肢体失能 | `[已拍板未实现]` 伤臂不能制作 | `grasp` 机制已备，但**当前没有任何物种使用它**（猪是四足，不抓握）；制作系统尚未存在 |

### 5.5 需求系统 `[已实现]`

- 需求清单来自数据（猪已挂 4 个：饥饿 / 口渴 / 保暖 / 疲劳）。
- 全部初始 100。衰减速率（2026-09-19 再调快，单位 = 每**游戏分钟**）：饥饿 **0.05**（≈1.4 天）/ 口渴 **0.07**（≈1 天）/ 保暖 **0.01389**（5 天 `[占位]`）/ 疲劳 **0.03472**（2 天）。
  → **不吃不喝 ≈ 1 天出头死亡**（渴 ~1 天先到、饿 ~1.4 天）。饥饿/口渴特意调快，好让猪在可观察时间内跌破觅食阈值（`SATIETY_STOP=0.95`）主动去找草吃；旧值（4/3 天）太慢、看着像"猪不吃饭"。
- **见底有后果**：标了 `depleted_is_lethal` 的需求（饥饿/口渴/保暖）耗尽 → `Needs.is_lethal()` 上报 → 宿主死亡，日志写明死因。
- 恢复走 `Needs.restore(id, amount)` —— **已被接上**：`Grazing` 啃草时调 `restore("food", …)`（§5.1e），`Brain` 睡觉时调 `restore("fatigue", …)`。吃/喝/取暖等其余入口仍待后续系统。
- 疲劳**不是**致命需求（设计如此），但**已接入行为**：疲劳越低 → 休息意愿越高、决策间隔越长 → 减速/更易停下；**夜里休息=睡觉，睡觉按 `SLEEP_RECOVER_RATE` 调 `Needs.restore("fatigue", …)` 回疲劳**（见 §4.5）。
- `[未决]`「保暖」是**恒定速率倒计时**，与环境/火/天气无关。名字已从「体温」改为「保暖」以反映真实语义（一个会持续流失的储量），真正的环境驱动温度系统尚未设计。
- `[已拍板未实现]` 水陆差异（鱼不挂 `Needs`，因此不需要口渴）——机制是通的（按物种挂组件），只是没有第二个物种来证明。

### 5.6 移动与决策 `[已实现]`

- 移动表现：**瞬移 + 停顿**（选定风格）。走一格即 snap 到位。
- 决策 / 决策间隔 / 昼夜反差：**见 §4.5**（`Brain` 的 5 驱动、轮盘权重、时长规则）。
- 移动前置：腿全断 → `can_move()` 为 false → 走不动（会长间隔空转）。
- 不会重叠：目标格必须空闲才进（**尸体不算占格**）。
- 不会越界：`is_cell_free()` 查 `in_bounds`。
- **踩尸规则（用户拍板 2026-09-19）**：`GridMover.free_directions()` 首选"又空又无尸体"的格；**只有被围死（首选为空）时**才把尸体格作为万不得已的退路。
- `move_to()` 成功后发 `EventBus.creature_moved`（小地图重画；将来脚印/噪音/领地判定听它，即 CDDA 的 on_move 钩子，**已实现**）。

### 5.6b 调试可见性：只读合成属性 `[已实现]`（2026-09-19）

**问题**：组件是 `RefCounted`，**不在场景树里** —— 运行时在调试器的远端场景树中根本看不到它们，「生物在动，但不知道它内部怎么了」。

**解法**：`Creature._get_property_list()` 把关键状态注册成**只读合成属性**，`Creature._get()` 提供取值。运行中在调试器里选中一只生物，检查器即可实时看到（下表为实测输出）：

| 属性 | 实测值 |
|---|---|
| `debug/id` / `debug/tag` | `1` / `猪#1` |
| `debug/coord` / `debug/alive` | `(20, 12)` / `true` |
| `debug/components/grid_mover` | `可动=是 可走方向 4` |
| `debug/components/brain` | `上次=wander 下次 1.2s` |
| `debug/components/personality` | `攻0.00 勇0.77 强0.63 活0.17 焦0.07 同0.79 合0.63` |
| `debug/components/perception` | `邻居 0 (R=6)` |
| `debug/components/body` | `血=380/380 部位{头40 躯干120 前左腿50 前右腿50 后左腿60 后右腿60}` |
| `debug/components/needs` | `需求{饥饿100 口渴100 保暖100 疲劳100}` |

- `usage = PROPERTY_USAGE_EDITOR | PROPERTY_USAGE_READ_ONLY`（4.7.2 实测取值 **268435460**）：检查器里可见、不可改；**不含 `STORAGE`** → 不会被写进 `.tscn`。
- 每行的值来自组件自己的 `debug_state()` —— 基类**仍然不认识任何具体组件**，加新组件不必改基类。
- 组件自述**别留空**：空行在检查器里等于白占位（`GridMover` / `Brain` 原先返回空串，本次已补）。
- **为什么不把组件做成子节点**：每只生物 +4 个节点，1500 只就是 6000 个。官方《Node alternatives》明确说「不需要进场景树的东西用 RefCounted / Resource」。

  - 部位行**两种形态都显示** —— 死后数值本来就冻结了，正好当验尸
- 订阅 `EventBus.creature_died`，选中的生物一死就切尸体视图（另有 `_refresh()` 兜底校正）

**`PixelBar`**（`class_name PixelBar extends Control`，自绘）
- `segments`（段数）、`cell: Vector2(8,8)`（每段方块）、`gap: int = 2`

**`game_theme.tres`**（**项目默认主题**：由 `project.godot` 的 `gui/theme/custom` 全局提供，**不在场景里挂任何节点**）
- `default_font = HYPixel11pxU-2.ttf`（汉字像素字体，11px 规格）、`default_font_size = 22`
- **纯黑白**（用户拍板「要像素、黑白、不要灰」）：`Label`/`Button` 字色 `Color(1,1,1)`；Button 悬停**反白黑字**；StyleBox 圆角 0、白描边 1px（按下 2px）；PanelContainer 黑底白边。全程只有 `#000`/`#FFF`。

**`Minimap`**（`class_name Minimap extends Control`，`ui/minimap.gd`）`[已实现]` — 右上角小地图
- 【用户拍板 2026-09-19】**只显示当前视野（"视线内"）那一片**，不再画整张 130×130 世界（那样又大又没意义）：只画**相机此刻看得见**的格矩形，随相机平移 / 缩放跟着变。
- **尺寸自适应**：长边最多 `MAX_SIDE = 150px`（开局 40×24 视野 → 每格 ≈3.75px），外框**白色** `Color.WHITE`。
- **地形底图仍烘成"全图" `ImageTexture`**（每格 1 像素、`TEXTURE_FILTER_NEAREST`）：地形一变（`terrain_changed`）才重建；`_draw` 用 `draw_texture_rect_region` 只取**可视子矩形**画出来 → 相机动只换取样窗口，不重建底图。
- 生物俯视点：活体 = `def.map_color`；尸体 = `Creature.DEAD_COLOR` 暗灰（**只画可视范围内**）。
- **重画时机**：`terrain_changed`（重建底图）+ `creature_spawned / moved / died / removed`（只重画点）+ `_process` 轮询可视矩形（**相机没有信号**，故每帧比 O(1)、变了才重画）。**不订阅 tick**，暂停时事件不来、小地图自然冻结。
- **只读**：读 GridManager（地形 / 生物）+ 读当前相机的可视矩形，不持有任何引用；`_get_minimum_size` / `_draw` 都有 grid 空守卫。
- **关于"隐蔽"**：主画面里藏进高草的生物**完全看不见**；小地图是开发者俯视图，**仍显示**它们（否则无法观察隐藏行为）—— 这是一处**刻意的不一致**。

### 5.8b 地图渲染 `[已实现]`（贴图地图）

### 5.8c 相机 `[已实现]`（2026-09-19）

**`CameraRig`**（`class_name CameraRig extends Camera2D`，`world/camera_rig.gd`，挂在 `main.tscn` 的 `Camera2D` 上）
- 130×130 = 4160×4160 世界像素装不进 1280×768 视口 → 用户拍板「**地图变大但视野不变**：默认一屏仍是原来的 40×24 格（1280×768），只许平移 / 放大，不许缩小**。
- **开局 `zoom = Vector2.ONE`（=1.0）**：视野与地图变大前一致；相机摆**地图正中**（(65,65) 附近）。注意 2026-09-19 起草原已甩到离正中半径 50 的环上、**开局这一屏看不到草原/猪**（相机不跟随，用户定），需 WASD/中键平移出去找。**没有 `_fit_all()`** —— 不把整张 4160×4160 塞进一屏（那是"相机变大"，用户不要）。
- **`MIN_ZOOM = 1.0`**：滚轮**向下被钳到 1.0**，即"不许比开局那一屏更小"。滚轮向上可放大看细节到 `MAX_ZOOM = 4.0`。
- **操作**：滚轮 = **以鼠标为中心**缩放（缩放前后让鼠标下的世界点不动，但下限 1.0）；**中键拖动**平移；**WASD / 方向键**平移（900 px/s，按 zoom 折算）。
- **UI 不受影响**：界面在 `CanvasLayer` 里，相机只动世界。
- **点击选取不受影响**：`Creature._unhandled_input` 用 `get_canvas_transform().affine_inverse()` 反算世界坐标，而相机正是 canvas transform 的一部分 → 缩放/平移后点选依旧对得上。
- `[未决]` 没有「跟随某只生物」的跟随目标（等玩家角色出现再说）。

### 5.8d 生物表现与点击选取 `[已实现]`

**生物表现（`Creature._render()` + `_draw()`）**：**有图就用图**（猪 = `creature/pig/art/pig.png` 剪影，Sprite2D 缩放成一格，`pig.tscn` 里有 `Sprite2D` 节点）；没配 `texture` 的物种才用 `map_color` 色块兜底（格子中央 `BODY_SIZE=20px`），死亡变 `DEAD_COLOR`。小地图不看图，一律用 `def.map_color`。

**点击选取的实现**（因为 `input_pickable` 赋不了值）：
```gdscript
func _unhandled_input(event: InputEvent) -> void:
    var world_pos: Vector2 = vp.get_canvas_transform().affine_inverse() * event.position
    if GridManager.grid.world_to_grid(world_pos) == coord:
        EventBus.creature_clicked.emit(self)
        vp.set_input_as_handled()
```
即：屏幕坐标 → 世界坐标 → 反算格子 → 与自身 `coord` 比对。复用网格系统，不依赖 picking 属性。

> **用 `_unhandled_input` 而不是 `_input`** 是刻意的：Godot 的输入顺序是 `_input` → GUI(Control) → `_unhandled_input`。被面板/按钮消费掉的点击**不会到达** `_unhandled_input`，所以点检视窗不会「穿透」选中窗下的生物。`set_input_as_handled()` 保证一次点击只选一个。

## 六、关键规则与约定

> 这一节是**写代码时必须遵守的**纪律。违反它 = 架构腐化。

### 6.1 三条归属线 + 判定三问

对任何「要不要加进基类」的疑问，问三句：

1. **是不是每个生物都无条件需要它？** 是 → 基类；否 → 往下问。
2. 它一种是**能力/需求**（有状态、会持续做事），还是**一堆数值**？ 能力/需求 → **组件**；数值 → **数据**。
3. 它是不是只在某一类物种成立、且行为差异极大？ 优先 **组合**，别急着开子类。

| 归属 | 机制 | 装什么 | 例子 |
|---|---|---|---|
| **基类字段** | `Creature` 成员 | 100% 通用状态 | `coord` / `alive` / 组件表 |
| **组合组件** | `CreatureComponent` | 「有时候需要」的能力 | 部位、需求、移动、大脑、家的位置 |
| **数据** | `*Def` Resource | 数值、配置、清单 | `max_hp` / `is_vital` / `drain_rate` / 挂哪些组件 |

**反例（永远不许再犯）**：「家的位置」写进基类 → 每条鱼都背一个没用的 `home_position`。基类会随「部分物种特性」不断胖成 god class。

### 6.2 组合优于继承

- 继承的翻车案例：企鹅是鸟不会飞、鲸会游不是鱼、飞鱼像鸟又像鱼 → 继承树会裂。
- **物种差异靠「挂哪些组件 + 配什么数据」，不靠继承树。**
- 真要继承，只留一层稳定原型，且子类里也不能塞「部分物种才要」的东西。当前代码**零子类**，只有 `Creature` 一个基类 —— 这是正确状态。

### 6.3 生死纪律（最重要的一条）

- `die()` 是全项目**唯一**把 `alive` 改成 false 的地方。
- **组件永远不许调用 `creature.die()`。** 组件只重写 `is_lethal()` 报告事实。
- 判定（`is_dead_state`）与接线（`check_dead_state`）都在基类；tick 循环里**不放任何 `alive` 判断**。
- 死掉的生物靠 `TimeSystem.tick.disconnect()` 摘出时钟，不是靠每帧自检。

### 6.4 数据纪律

- 内容（数值/清单/挂哪些组件）写在 `.tres`，**不硬编码在脚本里**。
- `.tres` 之间用**独立文件 + `ExtResource` 按路径引用**；**不许用内联子资源**（见 §2.4 坑 1）。
- `Cell.terrain` 这类**预留字段**：可以先留，但**必须承认它是休眠的**，不许在文档里宣称已完成。
  更进一步的纪律：**如果一个字段会让某段代码说谎，就删掉它**（`BodyPart.infection` 就是这样被删的 —— 它让 `status_text()` 里出现了一个永远不可能的「感染」状态）。

### 6.5 解耦纪律

- 系统/UI 之间不直接互相调用 → 走 `EventBus` 信号。
- 逻辑不认识 UI：`Creature` 不知道有检视面板；面板自己订阅 `creature_clicked`。
- UI 不认识物种：面板读 `get_component(Body)` / `get_component(Needs)`，换物种不改 UI。
- 工具栏不认识生成逻辑：委托 `Main.spawn_pig_random()`。
- 移动不认识决策：`GridMover` 只管执行，`Brain` 只管选方向。
- 组件之间靠 `requires()` **显式声明**依赖，而不是到处 `get_node`。

### 6.6 变更纪律（只新增、少改动）

优先**在现有结构上增加功能**，而不是改动已有代码。判据：
- 加一个物种 = 新增 `CreatureDef` + 场景，**不碰任何系统代码**。
- 加一种死法 = 新增组件重写 `is_lethal()`，**不碰 `die()` 与 tick 循环**。
- 加一种行为 = 换一个 Brain 组件，**不碰基类、不碰移动组件**。
- 加一种需求 = 新增 `NeedDef` + 挂进物种数据，**不碰 `Needs` 组件代码**。

### 6.7 数值纪律

- 所有数值初值都是 `[占位]`，**必须跑出来再调**，不许凭想象定平衡。
- 任何「待定」的数值就在文档里标 `[占位]`，不要假装它是最终值。
- 出处不明的机制**不许写**。要写就注明来源（源码 / 访谈 / 实测），来源不明确的标注为「未核实」。

### 6.8 表现与逻辑分离

- 逻辑层不依赖渲染。删掉 `MapRenderer`、`Minimap` 和 `Creature._draw()`，模拟照样跑。
- 表现入口有三处，全部**只读**：`MapRenderer._draw()`（格子）、`Creature._draw()`（生物色块）、`Minimap._draw()`（缩略图）。`def.texture` 可以是 null。

### 6.9 加一只新物种的标准流程

1. 备部位：新建 N 个部位 `.tres`（或将来的 `BodyPlanDef` 具名模板，见 §8.3）。
2. 备需求：新建/复用需求 `.tres`。
3. 新建 `X_def.tres`：`script = creature_def.gd`；填 `display_name`、`texture`（可空，空则主画面显示 `map_color` 色块）、`map_color`（小地图色点，默认白）、`component_scripts`（拖 `.gd` 脚本本体）、`body_parts`、`active_needs`。
4. 新建 `X.tscn`：根 `Node2D` + `creature.gd`，`def = X_def.tres`，加子节点 `Sprite2D`（配了 texture 才需要）。
5. 生成它：走 `Main._spawn_pig(at)`（内部 `add_child` 到 `$Creatures`）；调试工具栏的「刷猪」按钮就是调 `Main.spawn_pig_random()`。
6. **不改任何系统代码。** 若做不到第 6 条，说明架构有问题，先改架构再继续。

### 6.10 校验纪律（这一条是本项目最容易自欺的地方）

1. **校验器必须被证明过能抓到错。** 写完一个校验器，要**故意注入一个错误**跑一遍，看到它真的喊出来，才算完成。
   否则你得到的可能是个「永远说通过」的校验器 —— 比没有校验更危险，因为它会给你虚假的安全感。
2. **「0 条问题」和「根本没查到东西」必须长得不一样。** 扫描类代码遇到「一个目标都没扫到」时应当**报错**，而不是安静地返回 0。
   `DefValidator` 就专门守这一条：扫不到 `.tres` 会直接 `push_error`。
3. **统计口径要写对。** 「N 个文件」指的是扫到的总数还是有问题数？写错就会得出「扫描 0 个文件、0 条问题」这种自我安慰的输出。
4. **改完必须实跑，并给出断言式输出。** 不接受「我认为应该没问题」：临时插一段打印（`[验证] xxx=…（应 …）`），跑出来看到实际值，再删掉临时代码。
5. **临时验证代码用完即删。** 留在里面就是下一次事故的种子。

## 十、当前基线（一句话总结）
