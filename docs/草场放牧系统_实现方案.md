> 状态：**G1~G4 已实现并 headless 实测**（见 `事实文档.md` §5.1e）；**G5 平衡调平 + §9 若干项待办**。

## 0. 需求还原（用户原话 → 系统机制）

| 用户描述 | 机制 |
|---|---|
| 猪会吃草 | 猪新增「进食(feed)」行为驱动：饿了走向可食草格、站上去周期性啃食，恢复 `food` 需求 |
| 一个草能被吃多少次就消失 | 每格草有**耐久度** `durability`（0..MAX_BITES），每次啃食 −1，归 0 = 被吃秃（depleted） |
| 一段时间不吃就会长好 | **再生**：不被啃时按计时器 +1 耐久；从 0 长回成熟需 `RECOVER_PER × MAX_BITES` 分钟 |
| 成熟后从周围 9 格选一个没被占领的地方扩散 | **蔓延（元胞自动机）**：成熟格每隔 `SPREAD_INTERVAL` 以 `SPREAD_CHANCE` 概率，在 3×3 Moore 邻域里挑一个**未被占领**的可种植格，新种一格 |

## 1. 资料依据（联网检索，均为量级参考，不照抄数值）

- 轮牧「恢复期 / 放牧周期」：一次放牧很短（数小时~1 天），牧草恢复到可再放牧的留茬通常需 **约 15~45 天**（温带、生长季），核心是「短吃—长歇」节奏。来源见下方 Sources（UMass / UGA / 轮牧周期科普）。
- 牧草日增长：生长季约 **20~80 kg DM/ha/天**（春快夏慢），规划常用中值 ~30~50。来源：GrasProg 牧草模型。
- 过度啃食伤根：啃得过低（去顶/去生长点）会**显著拖慢再生**——支持我们「耐久归 0 后再生更慢或需重新定植」的设定。来源：Leymus chinensis 去顶/唾液实验、Frontiers in Plant Science 再生资源再分配。
- 载畜量 / 承载力：放养密度须 ≤ 牧草供给，否则草地退化——对应本系统的**平衡约束**（见 §6）。来源：UGA Understanding Stocking Rate。
- 植被扩散：元胞自动机常用 **3×3（Moore）邻域** + 每步定概率，成熟斑块向邻近空白格定殖（一年生杂草扩散、Spartina 扩张模型等）。来源：见 Sources 中多篇 CA 植被/扩散论文。
- 猪采食：猪为杂食、可采食牧草但占比不高，日粮约 2~2.5 kg/天；本游戏把「草」抽象成可恢复 `food` 需求的能量来源，具体恢复量按玩法调（见 Sources 中文采食量问答，仅作量级）。

> 结论：真实世界「恢复数十天」对玩法太长，须压缩到**游戏分钟尺度**（1 天 = 1440 分）；本规划给的是**量级合理、可跑的占位值**，全部标 `[占位]`，落地后用无头模拟调平（见 §8）。

## 2. 时间尺度换算（对齐现有 `TimeSystem`）

- 1 真实秒 = 1 游戏分钟；1 游戏天 = 1440 游戏分 = 24 真实分。
- 现有猪 `food` 衰减 = **0.01736 / 游戏分**（满 100 → 见底 ≈ 5760 分 = 4 游戏天）。
- 下文「分钟」一律指**游戏分钟**；所有周期用同一个时钟（`TimeSystem.tick`），天然支持暂停/倍速（机制已在，UI 暂不加）。

## 3. 实体定义

### 3.1 数据层（Resource，全局共享「是什么」）——仿 `CreatureDef`/`NeedDef`

```gdscript
# world/grass/grass_def.gd
class_name GrassDef
extends Resource
## 一种草的静态定义（物种级）。加一种草 = 配一份 .tres，不改代码。

@export var display_name: String = "牧草"
@export var texture: Texture2D            # 成熟贴图（可空 → 色块兜底）
# —— 耐久与再生 ——
@export var max_bites: int = 4            # 成熟耐久（=能被啃几次到秃）[占位]
@export var edible_min_bites: int = 1     # 耐久 ≥ 此值才可被啃 / 可扩散
@export var recover_per_bite_min: float = 60.0   # 每恢复 1 点耐久所需游戏分（不被啃时）[占位]
@export var depleted_extra_penalty: float = 1.5 # 归 0 后再生乘数（伤根效应，>1=更慢）[占位]
# —— 扩散 ——
@export var spread_interval_min: float = 120.0  # 成熟格每隔多少分尝试扩散一次 [占位]
@export var spread_chance: float = 0.20         # 每次尝试成功概率 [占位]
@export var spread_radius: int = 1              # 邻域半径（1 → 3×3=9 格）
@export var seed_bites: int = 1                 # 新定殖格的起始耐久
# —— 喂养 ——
@export var food_per_bite: float = 5.0          # 啃一口恢复多少 food 需求 [占位]

func validate() -> Array[String]:
    var errs: Array[String] = []
    if display_name.strip_edges().is_empty(): errs.append("display_name 为空")
    if max_bites <= 0: errs.append("max_bites 必须 > 0")
    if edible_min_bites < 1 or edible_min_bites > max_bites:
        errs.append("edible_min_bites 需落在 [1, max_bites]")
    if recover_per_bite_min <= 0: errs.append("recover_per_bite_min 必须 > 0")
    if spread_interval_min <= 0: errs.append("spread_interval_min 必须 > 0")
    if spread_chance < 0.0 or spread_chance > 1.0: errs.append("spread_chance 需 0..1")
    if spread_radius < 1: errs.append("spread_radius 至少 1")
    if food_per_bite <= 0: errs.append("food_per_bite 必须 > 0")
    return errs
```

`world/grass/grass_common.tres` —— 一份实例（猪吃的草），当前全图就这一种。

**与地形注册表的关系（关键设计点）**：`Terrain` 仍是「地表基底」的唯一事实来源。新增一个**数据字段** `plantable: bool` 到 `Terrain.DEFS`（`unknown=true`、`grass/tall_grass=true`，将来水/岩壁=false），扩散只落进 `plantable` 的格。→ 加地貌不改扩散逻辑，符合「加一行数据」纪律。`tall_grass`（现用于隐蔽）与本草场的**归并**见 §9 待拍板 Q1。

### 3.2 运行时状态层（RefCounted，不进场景树，仿 `BodyPart`/`Need`）

```gdscript
# world/grass/grass_tile.gd
class_name GrassTile
extends RefCounted
## 单格草的当前状态。由 GrassField 持有与推进。
var def: GrassDef
var coord: Vector2i
var durability: int          # 当前耐久 0..max_bites
var _recover_acc: float = 0.0   # 再生计时累加器（游戏分）
var _spread_acc: float = 0.0    # 扩散计时累加器
var _grazed_flag: bool = false  # 本恢复周期内是否被啃过（用于「不吃才长好」+ 伤根）

func is_mature() -> bool: return durability >= def.edible_min_bites and durability >= def.max_bites
func is_edible() -> bool: return durability >= def.edible_min_bites
```

### 3.3 世界层服务：`GrassField`（Autoload，唯一持有并推进草场）

> 为何做成 Autoload：草场是**真正全局的世界状态**（与 `GridManager` 同级），且要订阅 `TimeSystem.tick`。保持「薄」——只做草的持有/推进/查询，不碰 UI、不碰生物决策。

```gdscript
# world/grass/grass_field.gd   (Autoload: GrassField)
extends Node
var tiles: Dictionary = {}          # Vector2i -> GrassTile（只存"有草"的格，避免每 tick 扫全图）
var rng := RandomNumberGenerator.new()   # 种子来自统一世界种子（见 §7 可复现）

func _ready() -> void:
    TimeSystem.tick.connect(_on_tick)
    rng.seed = WorldSeed.value      # 单一来源，见 §7

func _on_tick(dt: float) -> void:   # dt = 游戏分钟
    var depleted_now: Array[Vector2i] = []
    var matured_now: Array[Vector2i] = []
    for coord in tiles.keys():
        var t: GrassTile = tiles[coord]
        _recover(t, dt)               # 不吃则回耐久
        if t.is_mature():
            matured_now.append(coord)
            _try_spread(t)            # 成熟才扩散
    # 事件（批量发，供表现层重画；见 §5.4 节流）
    ...

func is_edible(coord: Vector2i) -> bool: ...
func mature_nearest(from: Vector2i, radius: int) -> Vector2i:   # 供猪寻的，-1 表示没有
func bite(coord: Vector2i) -> Dictionary:   # {food_gained:float, depleted:bool}；耐久−1，触发事件
func establish(coord: Vector2i, def) -> void:   # 定植一格（初始耐久 = seed_bites）
func count_mature() -> int: ...
func debug_state(coord: Vector2i) -> String: ...
```

### 3.4 猪侧：`Grazing` 组件 + `Brain` 新增 `Feed` 驱动

```gdscript
# creature/components/grazing.gd
class_name Grazing
extends CreatureComponent
## 啃食：站在可食草格上、按 BITE_INTERVAL 咬一口，经 GrassField.bite + Needs.restore('food')。
## 【解耦】不认识 Brain、不认识 Body；只跟 GrassField(服务) 与 Needs(宿主组件) 打交道。
const BITE_INTERVAL := 8.0    # 游戏分/口 [占位]
var _bite_timer: float = 0.0

func requires() -> Array: return [Needs]      # 硬依赖：要有 food 需求可恢复
func has_def() -> bool: ...                    # 是否配置了吃的草（GrassDef）

func tick(dt: float) -> void:
    _bite_timer -= dt
    if _bite_timer > 0: return
    var here: Vector2i = creature.coord
    if GrassField.is_edible(here):
        var r := GrassField.bite(here)
        (creature.get_component(Needs) as Needs).restore("food", r["food_gained"])
        _bite_timer = BITE_INTERVAL

# —— 供 Brain 用的两个协议化钩子（不暴露 GrassField 细节给 Brain）——
func hunger_weight() -> float:                 # 越饿越大（0..）
    var food = (creature.get_component(Needs) as Needs).need_by_id("food")
    return 1.0 - food.ratio()
func has_nearby_forage() -> bool:              # 感知半径内是否有可食草
    return GrassField.mature_nearest(creature.coord, forage_radius) != Vector2i(-1,-1)
func forage_dir() -> Vector2: ...              # 朝最近可食草的单位方向（给 Brain 选步）
func debug_state() -> String: return "啃食间隔%.0fs 草=%s" % [...]
```

**Brain 扩展（只加一个驱动，不动其余）**：在 `Brain._decide_and_act` 的轮盘里加 `feed` 一项，权重 = `hunger_weight × FEED_GAIN`（仅当 `Grazing.has_nearby_forage()`）；选中时若已在草上则原地站着（`Grazing` 自会啃），否则朝 `forage_dir()` 走一步。→ Brain 仍**不认识 Grazing 类**（通过新协议钩子 `hunger_weight/forage_dir/has_nearby_forage` 问，仿 `allows_movement` 套路）。`pig_def.tres` 第 8 个组件挂 `grazing.gd`。

## 4. 草生命周期状态机

```
        spread_chance（成熟格向邻域空白定殖）
unknown(plantable) ──establish(seed_bites)──▶ Growing(durability<max)
                                                   │ recover_per_bite_min：每 +1 耐久
   啃食 bite() −1 ◀────────────────────────────────┤
                                                   ▼
                       Mature(durability==max) ──可扩散──▶（回到 spread_chance）
                                   │ 连续啃到 0
                                   ▼
                             Depleted(durability==0，"秃"）
                                   │ 仍按 recover 再生，但 ×depleted_extra_penalty（伤根更慢）
                                   └──────▶ Growing（长回来）
```
- 「吃几次消失」= 从成熟 `max_bites` 啃到 0。
- 「不吃就长好」= 不被啃时 `recover_per_bite_min` 计时，`_recover_acc` 满一轮 → `durability += 1`（封顶 max）。被啃则重置 `_grazed_flag`，再生可加惩罚（可选）。
- 「扩散」= 仅 `Mature` 触发；目标是 3×3 内 `terrain.plantable 且无 content 且无 corpse 且当前无 grass tile` 的一格，`rng` 掷 `spread_chance`。

## 5. 参数表（全部 `[占位]`，落地后用 §8 模拟调平）

### 5.1 草
| 参数 | 值（游戏分/次） | 说明 |
|---|---|---|
| `max_bites`（成熟耐久） | **4** | 吃 4 次到秃 |
| `edible_min_bites` | **1** | ≥1 才可啃/可扩散 |
| `recover_per_bite_min` | **60** | 回 1 点耐久/60 分；秃→成熟 ≈ 4×60=**240 分（0.17 天）** |
| `depleted_extra_penalty` | **1.5** | 归 0 后再生 ×1.5 慢（伤根，致敬真实模型） |
| `spread_interval_min` | **120** | 成熟格每 120 分试一次扩散 |
| `spread_chance` | **0.20** | 每次成功概率 |
| `spread_radius` | **1**（3×3=9 格） | Moore 邻域 |
| `seed_bites` | **1** | 新格起始耐久 |

### 5.2 猪
| 参数 | 值 | 说明 |
|---|---|---|
| `BITE_INTERVAL` | **8** | 每 8 分啃一口（站在可食草上时） |
| `food_per_bite` | **5** | 一口 +5 food（drain 0.01736/min → 吃到 ~70 只需 6 口=48 分）|
| `FEED_GAIN`（驱动权重系数） | **4.0** | 越饿越优先去吃；见 §6 平衡 |
| `forage_radius`（找草半径） | **8** | 复用/扩 Perception 半径概念 |
| 触发阈值 | food < 70 开始寻草 | 高活力猪可容忍更饿 |

### 5.3 平衡（承载力）公式——本系统**唯一真正要调的东西**
- 单格稳态供给 food/min ≈ `food_per_bite / recover_per_bite_min` = 5/60 = **0.083**。
- 单猪需求 food/min = **0.01736**。
- ∴ **1 片成熟草可持续养活 ≈ 0.083/0.01736 ≈ 4.8 头猪**；T 片成熟草养 ≈ 4.8·T 头。
  - 当前默认草原椭圆 ~150 格 → 承载 ~数百头；只有 12 头 → **全局不会饿死，但会「局部过啃」**：一伙猪啃到的格子掉到 0 的速度（每口 8 分 ×4）快于再生（240 分），于是出现啃秃→恢复→再扩散的**斑块动态（boom/bust）**，正是我们要的涌现。
  - 想更紧（让草明显萎缩/猪挨饿）：调**小** `recover_per_bite_min` 反向——即**增大**恢复耗时（如 60→180）或**减小** `food_per_bite`。想更松：反之。给 §8 的模拟脚本扫参定值。

### 5.4 渲染 / 事件节流
- `MapRenderer`/`Minimap` 按 `GrassTile.durability` 上色（秃→枯黄、成长中→浅绿、成熟→深绿；无草格走 `Terrain.color_of` 兜底）。
- 扩散/啃食/成熟/秃 各发一次 EventBus 信号（带 coord），**仅在耐久跨越整数点时**重画相关格（16900 格全量重绘只在低频做），避免每 tick 全图重绘。

## 6. 运行规则（每 tick 顺序，确定且可暂停）
1. `GrassField._recover`：所有草格再生计时（不吃才涨；秃格加惩罚）。
2. `GrassField._try_spread`：成熟格按各自 `spread_acc` 到点试扩散（`rng` 决定成败与选哪格）。
3. 生物 `_on_tick`（既有）：组件依次 `tick` —— 含 `Grazing`（到点且脚下可食 → `bite` + `restore food`）与 `Brain`（轮盘可能选 `feed`：饿了先走向最近可食草）。
4. `check_dead_state`（既有）：需求见底/要害致死等——饿死洞被吃草补上后更立体。

> 咬合：`bite` 由 `Grazing` 主动调（自持 `_bite_timer`），与 Brain 解耦；Brain 只管「要不要去、往哪走」。

## 7. 与现有架构的接线点（只新增、少改动）
- **EventBus**：新增 `grass_established(coord)` / `grass_depleted(coord)` / `grass_matured(coord)` / `grass_changed(coord)`（重画用）。
- **组件协议**：仿 `allows_movement/is_lethal`，为 Brain 增 `hunger_weight()/has_nearby_forage()/forage_dir()` 钩子 → 基类与 Brain 仍不认识 `Grazing`/`GrassField` 细节。
- **`Needs.restore("food", …)`**：早备好、一直没人调的接口，这里**第一次被接上**（吃=恢复 food）。
- **`DefValidator`**：`_validate_resource` 增 `GrassDef` 分支；扫描根从 `res://creature` 扩到含 `res://world/grass`（并把 §6.10「扫不到要报错」一并守）。
- **世界种子单一来源（顺手还 §8 的 [未决] 债）**：新建 Autoload `WorldSeed`（或挂 GridManager），`GrassField.rng` 与 `Creature` 生物源都从它取；彻底消掉「`Main.WORLD_SEED` 与 `Creature._world_seed` 各写一份」。
- **可复现**：`GrassField` 扩散/选格走 `rng`（seed=WorldSeed）→ 草场演化确定。⚠ 但**猪落点仍走全局 `randi_range`（现有 [已知问题]）**→ 猪-草交互不可复现。建议本次顺手把 `main` 出生点也改用种子化 RNG（见 §9 Q2）。
- **目录**：`world/grass/`（`grass_field.gd` Autoload、`grass_def.gd`、`grass_tile.gd`、`grass_common.tres`）；`creature/components/grazing.gd`。符合「顶层按领域 / 框架与实例分离」。

## 8. 分期里程碑（每期 headless 可验证，遵守 §2.3 / §6.10：临时探针用完即删、断言式输出）
- **G1 草场内核（不吃不扩散，先立起来）**：`GrassDef`+`GrassTile`+`GrassField`；`grassland_generator` 把当前草椭圆改造成在那些格 `establish(max_bites)`；`GrassField` 订阅 tick 做再生。探针：造一个秃格，跑 N 分，断言耐久按 `recover` 涨回、不越界、`--quit-after` 无报错。
- **G2 扩散**：成熟格 3×3 定殖。探针：给一小片成熟草、不喂猪，跑 N 游戏天，断言草地面积**单调上升但受 `plantable` 与占用约束**、可复现（同种子同结果）。
- **G3 猪吃草**：`Grazing` + Brain `feed` 驱动 + `bite`+`restore food`。探针：断言「有草时猪 food 能维持不饿死」「连续啃使某格耐久降到 0 再回涨」「food=0 时 feed 权重最高」。

## 10. 风险
- **性能**：只遍历 `tiles`（有草格，数百~数千），非全图 16900；扩散会让 `tiles` 增长——靠啃食/再生平衡与可选「草盖过全图即稳态」抑制；必要时加 `max_grass_tiles` 上限（占位）。
- **重绘风暴**：事件按 coord 局部重画 + 节流；不每 tick 全量。
- **过平衡**：草吃秃且不再扩散 = 全灭；靠 §5.3 公式 + §8 G5 扫参守下限。
- **耦合回潮**：坚持 Brain/基类不 import `Grazing`/`GrassField`，只走协议钩子；否则 §6.1 纪律破功。
