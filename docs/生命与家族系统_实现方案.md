# 生命与家族系统 · 设计与实现规划（年龄 / 成长 / 性别 / 亲缘 / 繁殖）

> 状态：**B1~B4 已实现并 headless 实测**（年龄+连续成长+老死 / 性别+亲缘+注册表 / 繁殖出生+遗传 / 族谱树 UI），见 `事实文档.md` §5.1f。**B5 平衡 + §7 开放项待办**。
> 本文件**吸收并取代**上一版 `年龄系统_实现方案.md`（那版只讲年龄；本版按用户新增需求扩到"性别 + 家族 + 繁殖"）。
> 唯一事实基准仍是 `事实文档.md`；落地后回写。
> 设计准绳：数据驱动 Resource、组件协议解耦、`TimeSystem` 固定 tick、可复现 RNG、`die()` 唯一执行、**基类不认识具体组件**、**生成只走 Main 一个口**、EventBus 解耦、只新增少改动、不提前抽象。

## 0. 需求还原（用户原话 → 机制）

| 用户要 | 机制 |
|---|---|
| 小猪要小小的，现在的 **¼ 大小**，慢慢长到现在这样大 | **连续成长曲线**：精灵缩放 `size = lerp(0.25, 1.0, age/成熟年龄)`，成年后停 1.0 |
| 猪要有**性别 男女** | 每只个体出生时定 `sex`（公/母，默认 50/50，可配）|
| **家族：爸爸妈妈、儿子女儿** | **亲缘链**：每只存 `mother_id / father_id / children_ids[]`；儿子=男性后代、女儿=女性后代；父母可解析（含"已故"）|
| （承上）**年龄** | `Aging` 组件：涨岁数 → 阶段 → 到寿命**老死**（走 `is_lethal()` 扩展点）|
| （隐含，有儿女才有爸妈）| **繁殖**：成年公母相邻 + 营养够 + 冷却到 → 生一胎幼崽，登记双亲 |

> 一句话：把"一只会走会吃会死的猪"升级成"有性别、会长大、会成家生子、会老死、有族谱的一群猪"。

## 1. 为什么能干净地塞进现有架构

- **老死** = 组件重写 `is_lethal()`（事实文档 §5.3/§6.6 的标准扩展点），`die()`/tick 循环零改动。
- **性别/亲缘/繁殖** 都是"部分生物才有的能力" → 做成**组件**，不进基类（§6.1 反例：别给每条鱼都塞 `mother_id`）。
- **繁殖要造新猪**：组件不自己 `add_child`，而是发 `EventBus.birth_requested(mother, father)` → **Main 监听并执行**（生成唯一入口，沿用 `_spawn_pig` 那套），完全符合"工具栏/组件不认识生成逻辑，委托 Main"的纪律。
- **亲缘引用**：`Creature.id`（全局自增，已存在）当键；新增一个 `FamilyRegistry` Autoload 维护 `id → 活体` 映射，供"查爸妈/儿女""找异性"解析。
- **可复现**：性别、寿命方差、遗传抖动全走 `creature.rng`（世界种子派生）。

## 2. 实体定义

### 2.1 `LifeDef`（Resource，物种级）—— `creature/life_def.gd`
```gdscript
class_name LifeDef
extends Resource
# —— 年龄与成长 ——
@export var lifespan_min: float = 8640.0     # 自然寿命(游戏分) [占位]=6游戏日
@export var mature_ratio: float = 0.20       # 长到这个年龄比例 = 成年(体型满格、性成熟)
@export var elder_ratio: float = 0.75        # 之后进入老年
@export var size_baby: float = 0.25          # 出生体型 = 成年的 1/4  ← 用户明确要
@export var size_elder: float = 0.9          # 老年微缩
@export var variance: float = 0.15           # 寿命个体差异 ±15%
# —— 性别 ——
@export var male_ratio: float = 0.5          # 出生雄性概率
# —— 繁殖 ——
@export var breed_cooldown_min: float = 2400.0  # 每胎间隔(游戏分) ≈ 1.7日 [占位]
@export var litter_min: int = 1              # 每胎最少
@export var litter_max: int = 3              # 每胎最多
@export var gestation_min: float = 1200.0    # 孕期(游戏分)；0=交配即生 [占位，可先不做孕期]
@export var breed_food_min: float = 0.6      # 双方 food 比例需 ≥ 才肯生（护住"吃饱才养得起娃"）
@export var breed_water_min: float = 0.5
@export var max_population: int = 200        # 种群软上限(防指数爆炸) [占位]
func validate() -> Array[String]: ...        # 比例有序、数值>0、litter_min<=max 等
```
`creature/pig/pig_life.tres` = 猪的一份。

### 2.2 `Aging`（组件）—— `creature/components/aging.gd`
年龄、连续成长、阶段、老死。
```gdscript
class_name Aging
extends CreatureComponent
enum Stage { JUVENILE, ADULT, ELDER }
var age_min: float = 0.0
var lifespan_min: float = 0.0
func tick(dt): age_min += dt                      # 到点 is_lethal 报老死
func stage() -> Stage
func is_lethal() -> bool: return age_min >= lifespan_min
func lethal_reason() -> String: return "老死（活了 %.1f 天）" % (age_min/1440.0)
func size_ratio() -> float:                       # 0.25→1.0 连续，老年微缩 → 表现层读它缩放
func speed_factor() -> float                      # 幼/老 决策间隔倍率 → Brain 读
func debug_state() -> String: return "年龄%.1f/%.0f天 %s 体型%.0f%%" % [...]
```

### 2.3 `Lineage`（组件，性别 + 亲缘）—— `creature/components/lineage.gd`
```gdscript
class_name Lineage
extends CreatureComponent
enum Sex { MALE, FEMALE }
var sex: Sex                       # setup 时按 def.life.male_ratio + creature.rng 定
var mother_id: int = -1
var father_id: int = -1
var children_ids: Array[int] = []
func is_male()/is_female() -> bool
func mother() -> Creature          # 经 FamilyRegistry 解析；已故/找不到 → null
func father() -> Creature
func children() -> Array[Creature]
func sons()/daughters() -> Array[Creature]   # children 再按 sex 分
func add_child_id(cid: int) / set_parents(m,f)
func debug_state() -> String: return "性别=%s 父母=(%d,%d) 子女=%d" % [...]
```

### 2.4 `Reproduction`（组件，交配/生娃行为）—— `creature/components/reproduction.gd`
```gdscript
class_name Reproduction
extends CreatureComponent
func requires() -> Array: return [Aging, Lineage]   # 硬依赖
var _cooldown: float = 0.0
func tick(dt):
    _cooldown -= dt
    if not _ready_to_breed(): return                # 母、成年(非老)、food/water够、冷却到
    var mate := _find_nearby_male()                 # 用 Perception 找相邻可育公猪
    if mate != null:
        _cooldown = def.life.breed_cooldown_min
        EventBus.birth_requested.emit(creature, mate)   # 只"请求"，真造娃在 Main
```
（公猪侧不主动发起，避免重复；也可双向，择一即可。孕期若做：`birth_requested` 先让母进入 `pregnant`，`gestation_min` 后 Main 才生成。）

### 2.5 `FamilyRegistry`（Autoload）—— `common/family_registry.gd`
`by_id: Dictionary[int → Creature]`；`Creature._ready` 注册、`NOTIFICATION_PREDELETE` 注销。提供 `get(id)`、`living_count()`、`mates_near(...)` 之类解析服务。让 Lineage/Reproduction 能按 id 找到活体，而不互相持有引用。

### 2.6 `CreatureDef` 加 `@export var life: LifeDef`（可空 = 该物种不启用这套，向后兼容）。

## 3. 出生流程（谁造娃、怎么登记）
1. `Reproduction` 判定"可育母 + 相邻可育公 + 营养 + 冷却" → 发 `birth_requested(mother, father)`。
2. **Main 监听** → `_spawn_offspring(mother, father)`：
   - 在母亲相邻找一个 `plantable`/可站的空格（复用 `spawn_pig_around_grass` 那类"绕心挑空格"逻辑）；
   - `PIG_SCENE.instantiate()`，`coord` 设好再 `add_child`（沿用 `_spawn_pig` 现有约束）；
   - 设 `Lineage`：`mother_id/father_id` = 父母 id；回填父母 `children_ids`；随机 `sex`；
   - **遗传**：`Aging.lifespan_min = 父母均值 × rng(1±variance)`；`Personality` 6 维 = 父母均值 ± rng 抖动（新增"由父母生成"入口，替代纯随机）；
   - 出生即 `age=0`、体型 `size_baby`；`EventBus.creature_spawned` 照发。
3. **种群软上限**：`_spawn_offspring` 前查 `FamilyRegistry.living_count() < life.max_population`，超了不生（防爆炸）。

## 4. 关键机制细节与取舍
- **连续成长**：`size_ratio()` 每 tick 变化 → 表现层需持续刷新缩放。做法：`Creature` 在 `_on_tick` 末尾（或 Aging 请求）调一次 `refresh_appearance()`，把 `_sprite.scale` 按 `size_ratio` 重设。点击选点仍按"反算格子"，不受缩放影响（现有逻辑）。
- **体型别溢出/别糊**：¼ 格的小猪要仍可辨认；NEAREST 过滤已全局开。
- **性比与找异性**：`male_ratio` 控出生性比；`Reproduction` 靠 `Perception.neighbors()`（已跳过隐蔽个体）过滤出"成年公"。
- **已故亲人**：父母死后从 registry 摘除，`mother()` 返回 null；族谱 UI 显示"已故(id#)"。children_ids 仍保留做谱系。
- **近亲繁殖**：MVP 可先不禁止（简单），列为未来项（`_find_nearby_male` 排除兄弟/父，需查共享 mother_id）。
- **防爆炸**：`breed_cooldown` + `max_population` + 营养门槛三重限流；否则 2→4→8… 指数失控、性能崩。
- **性能**：繁殖判定只在"成年个体、且过了冷却"时做邻域搜索，且 Brain 已"先判饿再扫草"式短路——同理"先判冷却/性别/年龄再找异性"。

## 6. 分期里程碑（每期 headless 可验、探针用完即删、断言式输出）
- **B1 年龄 + 连续成长 + 老死**：`LifeDef`+`Aging`+`CreatureDef.life`+校验；小猪 0.25→1.0 长大、到寿老死。探针：出生 size_ratio≈0.25、随 age 增到 1.0、lifespan 到点 `is_dead_state()` 真、死因"老死"、同种子寿命一致。
- **B2 性别 + 亲缘登记**：`Lineage` + `FamilyRegistry`；出生定 sex、记 mother/father/children、`sons()/daughters()`。探针：造两只标父母，查 `mother()/children()` 正确、死亲返回 null。
- **B3 繁殖出生**：`Reproduction` + `EventBus.birth_requested` + `Main._spawn_offspring`（含遗传 + 上限 + 落相邻空格）。探针：放一公一母成年饱腹相邻，跑够时间断言出现幼崽、幼崽父母指向它俩、种群不超上限、可复现。
- **B4 表现/族谱**：Inspector 增"性别/年龄/父母/子女数"，可选族谱面板；体型随成长实时缩放。
- **B5 平衡 + 遗传**：调繁殖率/冷却/上限/营养门槛，让种群能自我维持又不爆；性格/寿命遗传做"父母均值±抖动"。

## 7. 需要你拍板（有歧义，先问不擅自假设）
- **Q1 繁殖触发**：(a) 公母**相邻一格**即配对生（简单，推荐先做）；(b) 要"求偶/交配"多步行为；(c) 引入**孕期**（交配后母怀孕 N 分才生）。我建议 **a 起步、孕期留 B5 可选**。
- **Q2 谁发起**：只母发起 / 只公发起 / 双向。建议**只母发起**（防同胎重复计数）。
- **Q3 一胎几个 / 冷却**：默认 1~3、冷却 1.7 游戏日，可否？
- **Q4 种群上限**：软上限 200（超了不生）合适吗？还是按草地承载力动态？
- **Q5 遗传**：性格/寿命取"父母均值 ± 随机"（推荐，能看出家族相像），还是纯随机？要不要**近亲禁止**（兄妹/亲子不配）？
- **Q6 出生默认**：debug"刷猪"按钮刷的是**随机年龄**（有老有小、有公有母，推荐）还是幼崽/成年？
- **Q7 性比**：1:1 还是可调（比如母多便于扩群）？
- **Q8 族谱 UI**：这轮要不要做"选中一只 → 显示爸妈/儿女可点跳转"的族谱面板，还是先只存数据 + 检视面板文字？

## 8. 风险
- **指数爆炸 / 性能**：繁殖 + 大种群 → tick 成本飙升。靠冷却 + 上限 + 营养门槛 + "先判条件再搜索"限流；必要时加 `SimulationLevel`（远处降频，事实文档 §8.3 已列）。
- **亲缘引用失效**：只存 id、活体走 registry 解析，死亲优雅降级为"已故"。
- **基类膨胀**：`size_ratio`/`sex` 都**不塞基类**——表现层/Brain 通过 `get_component(Aging/Lineage)` 读（UI 早就这么读 Body/Needs，合规）；`visual_scale` 若要基类聚合需先确认真的通用，否则宁可让 `_render` 直接读 Aging。
- **一次吃太多**：这是 5 个子系统（年龄/成长/性别/亲缘/繁殖）。**强烈建议按 B1→B3 逐期落地**，B1（年龄+成长+老死）先做完就能看到"小猪长大、会老死"，再上性别家族繁殖。
